## 1. 文件路径 intern：`FileId` 注册表

**出处**：`config.paths.ai_mylua_lsp`/lsp/crates/mylua-lsp/src/uri_id.rs（mylua 的 `UriId`）

### 1.1 动机

mylua 是被 5 万文件量级逼出来的**性能**手段；本仓 441 文件，性能收益接近零。
**采纳的真正理由是架构不变量**：`FileId` 是 ID 体系四键之一（LSP实现规划 §3），
`DefData.file`、`UseSite`、per-file 文本/CST/语义缓存表全部以它为键——键的类型属于
接口不变量，后补 = 全量签名改动。

判据（后续同类决策沿用）：**接口不变量类优化必须第一天就上**；热点路径类优化
（LRU、缓存、失效策略）可以后补。

### 1.2 设计要点（照搬 mylua）

- append-only 注册表：`by_path: HashMap<&'static str, FileId>` + `by_id: Vec<FileMeta>`；
- intern 快路径只拿读锁，miss 再升级写锁 + 双检查；
- 路径字符串 `Box::leak` 成 `&'static str`——server 进程级生命周期，永不释放；
- 注册表为进程级全局 static（`OnceLock`）。

### 1.3 本仓适配改动

| mylua | 本仓 | 理由 |
|---|---|---|
| `UriPriority`：annotation 关键词计数 + 路径深度 + 长度 | **根序优先级**（root_index） | 冲突消解规则是确定的「项目根优先于引擎根」（架构设计 §4.2），不需要启发式 |
| 直接依赖 `tower Uri` 类型 | **intern 裸路径字符串**，`Uri ↔ path` 转换留在 as-lsp | as-core 纯库不依赖 LSP 协议类型 |
| `i32` + 非负断言 | `u32` | 无负值语义 |
| `INITIAL_CAPACITY = 25_000` | `1024` | 441 文件量级，Vec 自然增长即可 |

**落点**：`as-core/src/id.rs`（类型定义）+ `intern.rs`（注册表）。

### 1.4 墓碑语义（append-only 注册表如何处理文件删除）

append-only 与「文件会被删除/改名」冲突：id 不能回收（否则已发出的 `DefData.file`、
`UseSite` 变成悬垂索引），但也不能装作文件还在。约定（决策 D18）：

```rust
struct FileMeta {
    path: &'static str,
    root_index: u32,   // 根序优先级（§1.3）
    alive: bool,       // ← 墓碑位
}
```

| 事件 | 处理 |
|---|---|
| 文件删除 | `alive = false`；该 FileId 的 DefId 从主索引 / 引用倒排 / mixin 倒排 / module 表摘除。**id 与 path 保留** |
| 同路径文件重现 | 路径 intern 命中原条目 → 复用原 FileId，翻回 `alive = true` |
| 文件改名 | = 旧路径删除 + 新路径新增（模块名随路径变，见 LSP实现规划 §5.3），**不是**改 path 字段 |

**硬性约束**：所有遍历型查询（`workspaceSymbol`、references 候选集、`dump-index`）
必须过滤 `!alive`。注册表提供 `iter_alive()` 作为默认遍历入口，裸 `by_id` 迭代视为错误用法。

代价：长会话中反复增删文件会让注册表缓慢增长（每个曾存在的路径一条，含泄漏的 path 字符串）。
441 文件量级下可忽略，且 `Box::leak` 的路径本就是进程级生命周期。

## 2. 符号 intern：`Sym`

**出处**：`config.paths.ai_mylua_lsp`/lsp/crates/mylua-lsp/src/lua_symbol.rs（mylua 的 `LuaSymbol`）

### 2.1 动机（按重要性排序）

1. **一致性**（主要）：`Sym` 相等 = id 相等，主索引 `HashMap<Sym, Vec<DefId>>`、引用倒排、
   查找链全部按 u32 比较——与 `DefId`/`TypeId` 的「相等即同一」哲学配套；
2. **内存去重**：引擎 API 名字重复率极高（`FVector` 在 414 个 `.d.as` 中出现数千次），
   intern 后每名字一份；
3. 性能（次要）：441 文件量级，字符串比较本来就够快。

### 2.2 设计要点（照搬）

- `lasso::ThreadedRodeo`（读路径并发、`Spur` 为 u32 key）；
- `Debug`/`Display` 渲染回原字符串（日志与测试可读性）；
- 进程级全局 static。

### 2.3 适配改动

- 初始容量 `128 万符号 / 32MB` → **20 万 / 8MB**（arena 会增长，超配纯属浪费）；
- 命名：`Sym`（LSP实现规划 §3 已定名）。

**落点**：`as-core/src/intern.rs`。

### 2.4 as-core 纯库边界的修正

两个 intern 表都是 as-core 内的进程级全局 static（as-core 必须消费 `Sym`/`FileId`，
故不能像 mylua 那样放 server crate）。as-core 的纯库声明相应修正为：
**无 IO、无 async、允许只增 intern 表**。interning 幂等、append-only、
`ThreadedRodeo` 线程安全，对单测并行无副作用（mylua 已在 5 万文件级验证此模式）。
