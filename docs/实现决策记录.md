## 1. 逐条记录

### D1 Rust 单测源码内置（用户拍板）

- **背景**：单测若读取 `tests/` 等外部 `.as` 文件，会引入文件系统依赖，破坏封闭性与可复现性。
- **裁决**：Rust 单元测试中的 `.as` 测试代码**一律内置于 Rust 源码**（字符串字面量），
  禁止读取外部文件。与 `ai-mylua-lsp` 同一约定。
- **注意点**：414 个 `.d.as` 不可能内置——它们的角色是 **as-cli 批量校验语料**（开发期验收
  动作，非 CI 单测；`Saved/` 目录可能被引擎清空，不构成稳定依赖）。复杂真实形态需要进单测时，
  **摘录片段内置**，而不是读文件。
- **落盘**：AGENTS.md「测试规则（硬性）」。

### D2 放弃旧 LSP golden 对账（用户拍板）

- **背景**：原计划用 Hazelight 旧 LSP 对同语料采 hover/definition 快照作回归基准，
  但旧 LSP 的类型真值依赖引擎在线（TCP 27099），采集自动化受限。
- **裁决**：不做 golden 对账。验收三支柱：

| 支柱 | 内容 |
|---|---|
| 单测 | as-core 纯库单测 + as-lsp 集成测试，源码内置（D1），固化**预期行为** |
| 语料批量 | as-cli 对 `Script-Examples` / `AS-Cache`（414 `.d.as`）/ 引擎 `Angelscript/**.as` 做 dump-tree/dump-index 校验 |
| 体感验收 | 每里程碑在 VSCode 扩展中人工验收（LSP实现规划 §9） |

- **理由**：语义真值已有引擎源码 + `as-docs` 取证体系兜底；无 golden 的回归风险用
  「单测固化预期」对冲。Hazelight 扩展降级为**纯人工参考**（不作为验收基准）。
- **落盘**：架构设计 §0.2 行为基准行、§6 P3/P4 验收、§7、§8 风险 5；LSP实现规划 §9/§10/§11/§12。

### D8 `unresolved_object` 语义（Q3，取证完成）

- **是什么**：类型名的标记后缀，由 C++ 绑定层 `FObjectPtrType` 在**成员变量声明模式**下生成
  （`[UE]Private/Binds/Bind_BlueprintType.cpp:1854-1872`，`IsUnresolvedObjectPointer()` 标记，
  告知 AS 编译器按 TObjectPtr 解析）；语料如 `Bind_FLatentActionInfo.cpp:23` 的
  `"UObject unresolved_object CallbackTarget"`。脚本作者不书写它。
- **裁决**：TypeRef **不设新变体**——语法层记 flag；推导、成员补全、重载匹配一律按**基类型**
  （如 `UObject`）处理；hover/签名原样渲染后缀。完整约定见
  [`架构设计-引擎内部语法.md`](架构设计-引擎内部语法.md) §3（本次新增）。
- **诊断预留**：用户 `.as` 中出现该后缀属异常形态，P5 占号归 `AS09xx`（引擎无对应报错，
  非引擎行为复刻）。

### D12 `FileId` 注册表（路径 intern）

- **背景**：mylua 的 `UriId`（`uri_id.rs`）把脚本路径转成 int id。讨论焦点：441 文件量级是否值得第一天就上。
- **裁决**：**第一天就用**。它是**接口不变量**而非热点优化——`FileId` 是 ID 体系四键之一，
  `DefData.file`、`UseSite`、per-file 缓存表全部以它为键，后补 = 全量签名改动。
- **适配**：根序优先级替换 mylua 的 annotation 启发式；路径 intern 下沉 as-core
  （去掉 tower `Uri` 依赖）；容量缩配。
- **详见**：[`实现优化.md`](实现优化.md) §1（**本文件不重复展开，统一引用该文档**）。

### D13 `Sym`（符号 intern）

- **背景**：mylua 的 `LuaSymbol`（`lua_symbol.rs`，lasso `ThreadedRodeo`）。
- **裁决**：**第一天就用**。动机排序：一致性 > 内存去重 > 性能。as-core 纯库边界修正为
  「无 IO、无 async、允许只增 intern 表」。
- **详见**：[`实现优化.md`](实现优化.md) §2。

### D14 `auto` 推导链：表达式定型管线（含 range-for 协议取证）

- **背景**：`auto location = this.GetActorTransform().GetLocation();` 一例揭示：占位表示
  （`TypeKind::Auto`）已定，但推导链——`this` 定型、链式成员访问、range-for 元素类型——
  需要明确设计，且 hover/补全/重载排序依赖同一原语。
- **裁决**：Phase 3 以 `expr_type` 单一原语承载（自底向上 + per-file 缓存）；range-for
  元素类型按引擎 `Iterator()/Iterate()` 双跳协议（`[ENGINE]as_compiler.cpp:5745-5873` 取证，
  新迭代器模式默认，旧模式不建模）；推导失败降级**宁缺毋假**（hover 原样、补全不出）。
- **候选诊断**：`Range-based for value is not iterable`（引擎原文 `as_compiler.cpp:5836`），
  P5 占号时归段待定，先不占号（码表纪律）。
- **解析时机澄清**：扫描阶段（Phase 1/2）完全不碰表达式定型——auto 只允许局部变量与
  range-for，字段/形参/返回值/全局变量一律显式，持久索引中 auto 只是占位记录。
  解析只发生在请求驱动场景（inlay hints、hover、补全、诊断 = 打开的文件；
  references/rename 消歧触达未打开文件时也是惰性 + 缓存）。auto 推导是函数体局部
  自包含分析，无需流敏感。
- **详见**：LSP实现规划 §4.2。

### D15 `.d.as` 注解标签白名单 + tag/doc 分流

- **背景**：2026-09 对账 414 个实际 `.d.as` 与 `TypeDeclarationExporter.cpp`，发现早期设计稿
  （架构设计 §2.4 旧版）与产出物严重脱节：设计的文件头 4 个 tag（`@engine` / `@plugin` /
  `@floatIsFloat64` / `@exported`）**一个都不存在**；实际最高频的 `@editable`（12917 次）
  与 `@cache_format` / `@group` / `@notProperty` **完全未被文档收录**。同时透传的 C++ 注释里
  混有 doxygen tag（`@param` 6406 次、`@see` 460 次…）与任意标识符 tag（`@Indices`、
  `@bInLocked`、`@InFrameNumber`），且与语义 tag **紧邻同块出现**。
- **裁决**：
  1. 语义 tag 采**白名单**（架构设计 §2.4.3 的 15 项，含 4 项语料零出现但导出器已实现的）；
  2. 白名单外一律作 doc 正文；doxygen 常见 8 个 tag 在 hover 渲染为 markdown 结构，其余原样；
  3. **未登记 tag 忽略且不报诊断**——引擎注释噪声无法穷举；
  4. 语义 tag 的 value 解析失败即丢弃该 tag，不报诊断（数据源机器生成，出错是导出器 bug）。
- **理由**：数据源是机器生成且**不受本仓控制**，唯一稳健策略是白名单 + 静默降级。
  黑名单或「报未知 tag」都会随引擎注释变动而刷屏。
- **落盘**：架构设计 §2.4.3（全表 + 源码行号）、§2.4.4（分流规则）；
  LSP实现规划 §2.2（`decl_tags.rs`）、§3.2（`DefFlags`）、§9 M1 验收。

### D16 struct 单层查找 + 属性访问器反向默认

- **背景**：两处「反直觉但有取证」的语义，早期文档均写错或未写。
- **裁决一（struct 单层）**：继承闭包**只对 class 建**，struct 成员查找单层。
  取证：① `.d.as` 的继承输出经 `ASType->GetClass()->GetSuperClass()`，struct（UScriptStruct 支撑）
  走不到该分支，**导出物里 struct 永远没有父类**（`TypeDeclarationExporter.cpp:535-554`）；
  ② C++ USTRUCT 继承在绑定层用 `TFieldIterator` **已展平**成自有成员
  （`as-docs/struct类型专题.md` §6.3）。为 struct 建闭包是无效工作，且会掩盖「展平」事实。
- **裁决二（访问器反向默认）**：引擎配置 `bAllowImplicitPropertyAccessors = true`，
  **绑定函数默认全部是属性访问器**，导出器只在 `IsProperty()` 为 **false** 时写出
  `@notProperty`（`:218-224`，该处注释即权威说明）。
  → 查找链第 3 级必须按「**默认是候选，带 `NOT_PROPERTY` 的除外**」实现。
  反着做（默认不是、见 tag 才是）会让 `Actor.BaseValue` 这类访问全部失效。
  另一半工作导出期已完成：`asTRAIT_GENERATED_FUNCTION` 的 `Get*/Set*` 已被转写成属性声明
  （`:434-469`），LSP 不需再配对。
- **附带**：查找链同时补入 `this`/`super`（第 0 级）、mixin 伪成员（第 4 级，按首参类型倒排）、
  `local` 函数模块隔离——原五级链缺这三项的**落地表示**，只有约束描述。
- **落盘**：架构设计 §2.4.2、§2.4.5、§4.5（0-6 级表）；LSP实现规划 §4（Phase 2 产物）、§7.1。

### D17 `TextRange` 字节偏移 + 类型规范形式

- **背景**：① 原 `DefData.name_range: Range` 与 `range.rs`（UTF-16 换算）混用，
  与「as-core 不依赖 LSP 协议类型」的纯库边界冲突；② `const T&` 可表示为
  `Const(Ref(T))` 或 `Ref(Const(T))`，两者结构不相等 ⇒ 同一类型拿到两个 TypeId。
- **裁决**：
  1. as-core 内部一律 `TextRange = (u32, u32)` **字节偏移**；行列换算只在 as-lsp 边界发生；
     **行首偏移表**（每文件 `Vec<u32>`）列为 Phase 2 持久产物，否则每次换算 O(文件长度)；
  2. 类型修饰符强制规范顺序 `Ref → Const → Array → Named/Param/Wildcard/Auto`，
     只能经 `intern_type()` 构造（内部重排 + 折叠 `Const(Const(T))`），字面量构造私有化。
- **理由**：两条都属 **接口不变量**，适用 D12 立下的判据（「接口不变量类优化必须第一天就上」）。
  规范形式是「TypeId 相等即同一」的唯一保护，破了它整个类型系统的去重与缓存键都失效。
- **落盘**：LSP实现规划 §3.2.1、§3.3、§4（Phase 2 产物）、§8、§12 G7。

### D18 overlay 唯一真值 + 文件生命周期 + 冷启动重放

- **背景**：原 §5 只写了「didChange 后怎么失效」，缺三块必备机制：
  ① 未保存缓冲与磁盘内容的优先级；② `.as` 增删改名；③ 冷启动快照发布前到达的编辑。
- **裁决**：
  1. **overlay 唯一真值**：`didOpen` 后文本来自 overlay，`didClose` 回落磁盘并重读；
     `didSave` 不触发重读；文件监视事件命中有 overlay 的文件则忽略；
  2. **文件生命周期**：`.as` 增/删/改名分别处理（改名 = 删+增，因模块名随路径变、
     影响 `local` 可见域）；`.d.as` 任一变化 → 整目录重建，且必须 **500ms 防抖**
     （导出器会先清空目录再写 414 文件，客户端瞬间推来上千事件）；
  3. **FileId 墓碑**：注册表 append-only，删除只打 `alive = false`，不回收 id；
     同路径重现则复用并翻回 `alive`；遍历型查询必须过滤 `!alive`；
  4. **冷启动重放**：`Loading` 期间编辑照常写 overlay 并记入 `pending_dirty`，
     快照 `arc-swap` 换根后立刻用 overlay 重放该集合，再置 `Ready`。
     非语义请求（documentSymbol / folding / semanticTokens）在 Loading 期即可服务。
- **理由**：overlay 独立于索引存储，是「编辑永不丢」的根本；有了它，冷启动竞态只需
  「发布后重放一次」这一个动作，无需复杂的事件排队与版本对齐。
- **落盘**：LSP实现规划 §5.1/§5.2/§5.3、§6.1、§8、§9 M4、§12 G8；实现优化 §1.4（墓碑）。

### D19 `.d.as` 与 `.as` 是交叉关系（非子集）；模板声明头定性

- **背景**：`Core.d.as:646` 的 `struct TArray<T> { ... }` 引出「引擎是否支持脚本定义模板」的追问。
  取证结论是**不支持**，且顺带发现两处文档表述错误
  （`grammar/README.md` 与架构设计 §3 都写「`.d.as` 是 `.as` 的**子集**」）。
- **裁决一（模板定性）**：AS 有**两条互不相通的解析入口**——
  脚本走 `ParseScript → ParseClass`（`[ENGINE]as_parser.cpp:3734`，标识符后只接受
  `;`/`:`/`{`，**不认 `<`**）；模板声明头走 `ParseTemplateDecl`（`:176`，标识符后**必须**是
  `<`，且须以 `ttEnd` 收尾、**不认类体**），后者只被
  `asCScriptEngine::RegisterObjectType`（`as_scriptengine.cpp:1719`）调用。
  第三道锁：UE 预处理器类名正则不含 `<>`（`AngelscriptPreprocessor.cpp:723`）。
  ⇒ **脚本侧不能定义模板**（class/struct/函数皆不可），`.d.as` 里的 `struct TArray<T>`
  是**我们导出器渲染的文本**（`TypeDeclarationExporter.cpp:526-533`），引擎从不读 `.d.as`。
  该完整形态（声明头 + 类体）在引擎任何入口下都非法，**只在本项目的 `.d.as` 方言里合法**。
- **裁决二（关系修正）**：`.d.as` **不是** `.as` 的子集，而是与之**交叉**。
  `.d.as` 独有 4 项（`type_parameters` / `?` / `unresolved_object` / `@templateSpecialization` 块），
  `.as` 独有函数体、语句、delegate/event/asset、mixin/local、局部 `auto`、f-string 等。
  **两个后果**：① 反向推理不成立 ⇒ `.as` 中误写 `.d.as` 独有构造必须报语义诊断
  （码表 §7.1 新增两条待占号）；② **验收口径必须分开算**，一侧零 ERROR 不替另一侧背书。
- **裁决三（特化块消歧）**：实测 `struct TArray<T>` / `struct TMap<K,V>` /
  `class TSubclassOf<T>` / `class TArray<FVector>` 四形态**全部零 ERROR，文法无需改动**
  （关闭架构设计 §8 风险 9）。`type_parameter` 节点同时承载类型形参与具体实参，
  语义层按「声明前是否有 `@templateSpecialization` tag」消歧，不新增文法规则。
- **实现推论**：`TypeKind::Param` **只可能来自 `.d.as`**，`.as` 索引路径可直接断言其不出现；
  模板实例化输入恒为「`.d.as` 定义 + `.as` 侧具体实参」。
- **落盘**：架构设计 §3、§8 风险 9（关闭）/风险 10（新增）；
  引擎内部语法 §4（新增）+ §5（四件套总览）；`grammar/README.md`（新增「交叉非子集」节、
  偏差 §4 更新、语义合法性表 +2 行）；`as-docs/设计取舍与使用限制.md` §2.5.1（语言真值）；
  诊断码表 §7.1。

### D20 LSP 不读 `_manifest.dctx`；`floatIsFloat64` 转配置项（用户拍板）

- **背景**：D15 对账时把 manifest 定为「失效校验 + `float_is_float64` 数据源」，设计了四级校验链。
  复盘时用户指出：**LSP 的类型真值来源就该只有 `.as` / `.d.as` 源码**（§0.2 原始目标），
  读第二种文件格式是架构上的多余路径。
- **裁决**：
  1. **运行时完全不读 `_manifest.dctx`**，删除 `manifest.rs`；as-core 只认一种输入——源码文本；
  2. `float_is_float64` → **LSP 配置项** `floatIsFloat64: boolean`，默认 `true`
     （对齐引擎 `bScriptFloatIsFloat64` 默认值），在 vscode-extension 侧配置；
     **取消原 `"auto"` 三态**（其语义是「读 manifest」，数据源已不存在）；
  3. 格式版本 → 读 **`.d.as` 文件头的 `@cache_format` tag**，不设配置项。
     它与 manifest 首行 `AS_TYPE_CACHE v1` 同源，且已在白名单 tag 表内（架构设计 §2.4.3）
     ⇒ LSP 解析 `.d.as` 时顺带取得，既不需要额外文件，也不该让用户去填这种技术细节；
  4. `engine_version` / `exported_utc` / `files=` **忽略**；`type_count` / `member_count`
     降级为**开发期人工对账参照**（M1 验收），非运行时依赖。
- **为什么 `float_is_float64` 不能一起丢**（取证）：它不是元数据，而是**语义输入**——
  `.d.as` 里的浮点是原样透传的引擎类型名，**无法自证宽度**：

  | token | 语料出现 | 含义 |
  |---|---|---|
  | `float32` | 8589 | 显式单精度 |
  | 裸 `float` | 1825 | 宽度由引擎设置决定 |
  | `float64` | 2（均在注释） | ⇒ 导出器从不展开宽度 |

  决定性对比：`struct FVector { float X; }` 与 `struct FVector3f { float32 X; }`
  并存于 `Core.d.as`。引擎开关 `bScriptFloatIsFloat64 = true` 是 `UPROPERTY(Config)`，
  **可被项目 ini 覆盖**（`[UE]Public/AngelscriptSettings.h:159-161`），故不能硬编码。
- **代价（已接受）**：
  - `AS0901`（指纹过期）retired——指纹校验对正确性无影响，且 manifest 本无插件指纹，
    最常见的「改绑定不改引擎版本」本就检测不到；
  - `AS0905`（group 文件名冲突）retired——唯一数据源是 `files=` 列表，磁盘上无从判断
    丢了哪些 group。该缺陷归导出器侧修（架构设计 §8 风险 7），用户侧会遇到
    「少数模块类型找不到且无提示」；
  - 新增风险：`floatIsFloat64` 配错是**静默错误**（架构设计 §8 风险 11 / 规划 §12 G9），
    缓解靠默认值对齐 + 状态栏常显生效值 + M1 双取值用例，不设诊断（无法自动检出）。
- **新增码**：`AS0906`（`@cache_format` 高于支持版本，仍尽力解析不阻断）。
- **落盘**：架构设计 §2.4.1/§2.5/§5/§8（风险 6 关闭、7 修订、11 新增）/§9；
  LSP实现规划 §2.2（删 `manifest.rs`）/§3.3/§5.3/§8.1/§9 M1·M6/§12（G6 修订、G9 新增）；
  诊断码表 §7（`AS0901`/`AS0905` retired、`AS0902` 改、`AS0906` 新增）/§8/§10。

### D21 不做 `.d.as` 格式版本校验（用户拍板）

> **本条修正 D20 的第 3 条**（「格式版本 → 读 `.d.as` 文件头的 `@cache_format`」）。
> 按治理规则「决策只追加、已定条目不改写」，D20 原文保留，以本条为准。

- **背景**：D20 把格式版本来源从 manifest 迁到 `.d.as` 文件头的 `@cache_format`，
  并为此占号 `AS0906`。用户复盘时质疑：**版本号对 AS 源码而言无意义**，
  那是官方 LSP（TCP 二进制协议）才需要的东西。
- **裁决**：**完全不做版本校验**。`@cache_format` 仅被**识别**（避免其注释行被当作
  doc 文本混进 hover），**值不消费**；`AS_TYPE_CACHE` 同样忽略。`AS0906` retired。
- **理由（比「无意义」更强的论证）**：

  1. **`.d.as` 是源码，不是协议**。源码不需要版本协商——不会在 `.cpp` 头上写
     「C++ 格式版本 17」。版本协商是**跨进程二进制协议**的需求（官方 LSP 的
     TCP 27099 DebugDatabase 确实需要：引擎与扩展独立更新、二进制布局不兼容即崩），
     而我们读的是文本源码，parse 不出来读了版本号也不会变得能读。
  2. **D15 的 tag 规则本身已是版本无关的**——这是当时未意识到的红利：

     | 导出器未来的变更 | 旧 LSP 行为 | 版本号有用吗 |
     |---|---|---|
     | 新增 tag | 白名单外 → 静默忽略 | ❌ 优雅降级 |
     | tag 改名 | 同上 | ❌ |
     | 删除 tag | 查不到 → 走默认值 | ❌ |
     | 语法结构变更 | tree-sitter 报 ERROR → 解析诊断 | ❌ 已覆盖 |
     | 语义极性反转（`@notProperty` → `@isProperty`） | 静默错误 | **救不了**：只能说「不匹配」，说不出「怎么解释」 |

  3. **导出器是本项目自有代码**（`Demo_AS/Plugins/AngelscriptTypeExporter`），
     非第三方独立演进组件。格式变更与 LSP 改动同批发生，开发期即暴露。

  ⇒ 版本校验无任何消费场景，属纯粹的自造复杂度。
- **码号纪律**：`AS0906` 占号后**未进入实现即废弃**，理论上复用无害；
  但仍按码表 §1「不得复用已废弃的号」标 retired，下一个可用为 `AS0907`。
  理由：一旦开始逐例判断「废弃得够彻底吗、能复用吗」，纪律即失去刚性；
  而码号无限，省一个号毫无收益。
- **落盘**：架构设计 §2.4.1（含论证表）/§2.4.3/§2.5/§9；
  LSP实现规划 §2.2/§8.1/§9 M6/§13；诊断码表 §7（`AS0906` retired）/§8/§10/§11。

### D23 mixin 语义精确化（引擎取证）

> **本条修正 D16「附带」项**中对查找链第 4 级的描述。D16 原文保留。

- **背景**：D16 补查找链时把 mixin 写成「首参类型匹配当前类/其基类 → 作为**伪成员候选**」。
  用户追问「unreal-as 支持 mixin 吗」时做了完整取证，发现该描述有 5 处不准确，
  且漏了两件事。
- **关键澄清：`mixin` 一词对应三套互不相关的机制**——这是最易踩的坑：

  | # | 形态 | 状态 | LSP 处理 |
  |---|---|---|---|
  | 1 | `mixin class Foo {...}`（原版 AS） | ❌ 不存在，parse error | 文法不实现（已定） |
  | 2 | `mixin void Foo(AActor T)`（脚本侧） | ✅ 活功能 | 查找链第 4 级 + mixin 倒排 |
  | 3 | `UCLASS(Meta=(ScriptMixin="FVector"))`（C++ 侧） | ✅ 活功能 | **无需处理**（见下） |

  形态 1 的机器（`RegisterMixinClass` / `IncludeMethodsFromMixins` / `mixinClasses`）
  是上游遗留的**不可达死代码**——`ParseMixin`（`as_parser.cpp:3700-3714`）只接
  `ParseFunction()`，没有任何路径能产生 `snMixin` 节点。

  形态 3 在**绑定期**就被 `Helper_FunctionSignature.h:283-345` 转成目标类型的真成员方法
  （`EBindTargetType::MixinMethod`，摘掉首参）⇒ `.d.as` 里已是普通成员方法形态，
  走第 2 级成员查找即可，**不进 mixin 倒排**。引擎自带一大批此类库
  （`FVector`/`FRotator`/`FQuat`/`FTransform` 数学库、`GameplayTag*`、`InputComponent` 等），
  若误将其纳入倒排会造成重复候选。
- **裁决（形态 2 的五条准入条件）**，真值 `[ENGINE]as_compiler.cpp:13387-13450`：

  | # | 引擎条件 | D16 原描述的问题 |
  |---|---|---|
  | 1 | `funcs.GetLength() == 0` | 原文「作为伪成员候选」像是并列参与排序；实际是**纯 fallback + 短路**，第 2/3 级命中就绝不查 |
  | 2 | `objectType != 0 \|\| ThisObjectType != nullptr` | **原文漏了**：无 `obj.` 也无 `this` 时不查（如全局函数体内） |
  | 3 | `scope.GetLength() == 0` | **原文漏了**：`NS::Foo(obj)` 不走 mixin |
  | 4 | 沿 `GetParentNameSpace` 逐级回退 | **原文漏了**：mixin 查找自身也要爬命名空间链 |
  | 5 | `DerivesOrShadows(首参类型)` | 原文「当前类或其基类」偏窄——含 **shadow** 语义（AS 类 shadow C++ 类） |

  另补两项原文遗漏：**后置属性写法** `void Foo(T) mixin`（`as_parser.cpp:3249`/`5083`，
  与前置等价，索引期都要识别）；**首参可以是 struct**（过滤只要求 `IsObject()`，
  AS value type 亦满足）。
- **实现要点**：mixin 倒排的键**不预展开到子类**，而是「沿继承闭包逐级查倒排」——
  闭包已有，省内存且与 `DerivesOrShadows` 语义一致。
- **附带取证**：`asTRAIT_MIXIN` 在引擎编译器里只有一处额外用途——no-discard 判定时
  按 const 方法对待（`as_compiler.cpp:18627`）；符号查找不因该 trait 特殊化。
  UE 反射层效果仅限编辑器（`MixinArgument` + `DefaultToSelf` meta，
  `AngelscriptClassGenerator.cpp:3324-3331`），LSP 不消费。
  引擎自带 `.as` 脚本中形态 2 使用数为 **0**，但官方 LSP 有数十处 `isMixin` 逻辑
  ⇒ 是给项目脚本准备的活功能，不是遗迹。
- **落盘**：架构设计 §4.5（第 4 级重述）+ 新增 §4.5.1/§4.5.2（v0.7）；
  LSP实现规划 §4（倒排产物）/§7.1（短路 fallback 四条守卫）/§9 M3 验收（v0.9）；
  as-docs/原版对比 新增 §5.4、原 §5.4 顺移为 §5.5（v0.6）。

### D24 `.d.as` 仍全量重建，但理由重写；防抖降级为「只防重复做功」（用户拍板）

> **本条修正 D18 第 2 条**中「`.d.as` 任一变化 → 整目录重建」的**论证**（结论不变），
> 并修正 D20 遗留的因果表述。D18/D20 原文保留。

- **背景**：用户质疑「`.d.as` 为何不能只看文件修改做增量？变更多才触发全量」。
  复盘发现原论证链有误——规划 §5.3 写的是「视为整个 `typeDeclarationDirs` 失效
  → 全量重建（**不读 manifest**，D20）」，即把「不做增量」归因于「没有 manifest
  这个数据源」。**该因果不成立**：判断增量根本不需要 manifest，
  `DidChangeWatchedFiles` 自带变更文件列表，磁盘 mtime/size 也能自查。
- **裁决一（结论不变，理由替换）**：`.d.as` 任一变化仍 → **整目录全量重建**，
  但理由改为以下两条：

  1. **增量路径几乎永不触发**：导出器执行时先 `DeleteDirectory` 清空目录再重写全部
     414 个文件（`TypeDeclarationExporter.cpp:330`）⇒ **变更集恒等于全集**，
     增量代码写了也用不上；且导出是**偶尔**的人工动作（菜单触发），不在热路径。
  2. **全量重建规避一整类 bug**：`.d.as` 逐文件摘除需同时摘净继承闭包、mixin 倒排、
     引用倒排、module 归属表，漏一处即产生幽灵符号；而 414 文件重建是秒级（规划 §4）。

  ⇒ 少一条代码路径，正确性不打折。原先讨论过的「变更数超阈值才降级为全量」方案
  **不采纳**：阈值以下的场景（手工 copy、git checkout 部分文件）稀少且重建本就秒级，
  为此维护两条失效路径不划算——与 D4「不为省秒级开销维护两套扫描口径」同一判据。
- **裁决二（机制定性澄清）**：`.d.as` 增量在**机制上并无特殊性**——它和 `.as` 编辑是
  同一类问题（「一个逻辑类型跨文件」不构成障碍：摘除 `Core.d.as` 只移除 `struct FVector`
  一个 DefId，同名 `namespace FVector` 不受影响；继承闭包级联已有 §5.2 的粗粒度联动
  失效机制覆盖）。故本条是**成本权衡**，不是「做不到」。将来若出现高频增量场景，
  可直接复用 `.as` 的增删改路径。
- **裁决三（唯一不可替代的全量触发源）**：`floatIsFloat64` 配置变更
  （`didChangeConfiguration`）。它是 `IndexConfig` 输入参数，改变每个文件里裸 `float`
  的归一化目标，与文件是否变动无关 ⇒ 无论 `.d.as` 增量做不做，这条必须全量。
- **裁决四（防抖保留，但职责降级）**：
  - 保留 **500ms 静默窗口**（窗口内事件只重置计时器），**新增 5s 硬上限**——
    累计等待超时即强制执行一次重建。理由：慢盘上写 414 个文件可能持续数秒，
    计时器被后续事件无限推迟 ⇒ 重建永不发生（原约定的隐患）。
  - **防抖不承担正确性职责**：重建在后台线程构造新快照、建好再 `arc-swap` 原子换根
    （规划 §6），旧快照全程可服务 ⇒ 「引擎类型瞬间全空」的中间态从根上不存在。
    防抖唯一价值是**避免重复做功**（别为上千条事件跑上千次重建）。
    这使正确性**不依赖 500ms / 5s 这两个时间参数调得准不准**——参数只影响响应延迟。
- **搁置项（不进本条裁决）**：「自动发现 `.d.as` 目录、免配置随意放置」。
  它与导出频率无关，但需先解决**多副本双源冲突**（`Saved/AS-Cache/Engine.d.as` 与
  版本库里 `Copy Declarations to Project` 留下的过期副本同时入索引 ⇒ `AActor` 双定义、
  补全重复、重载表污染，且属静默错误）。消解规则需占新码（`AS0907`，
  按码表 §1 纪律不复用 `AS0905`/`AS0906`）。用户决定**暂不做**，继续用
  `typeDeclarationDirs` 显式配置（行为完全确定）。
- **落盘**：LSP实现规划 §5.3（理由段重写 + 防抖补硬上限与定性）/§13（v1.0）。

### D25 基础类型是合成 builtin DefId，不是 `.d.as` 声明（修正 LSP实现规划 §3.3 的语料事实表述）

> **本条修正 LSP实现规划 §3.3** 的表述「基础类型在 `.d.as` 中有真实 DefId」——
> 该表述与实际导出物不符（规划原文已同步修正）。

- **背景**：M1 实现期对账语料（414 个 `.d.as` 全量检索）：`^(struct|class|enum)
  (float64|float32|float|int|bool|void|double)` **零命中**；`float64` 全语料仅
  2 次出现且均在注释里（架构设计 §2.5 早已记录该数字，但未推翻「有真实 DefId」
  的想定）。基础类型是引擎原生 primitive，不在 `asITypeInfo` 注册类型枚举里
  ⇒ 导出器（§2.2 遍历注册类型）从不导出它们。
- **裁决**：`primitive_type` 全集 16 个关键字中除 `float` 外的 15 个，在索引
  构建期注入为**合成 DefId**（`DefFlags::SYNTHETIC`，file = 伪路径
  `<as-core:builtin>`，name_span/full_span 为空区间）。类型表仍**统一走
  `Named{def}`，不设特例**——原设计的真实意图保留，改变的只是 DefId 来源。
  裸 `float` 从不落到名为 `float` 的 DefId：解析层按
  `IndexConfig.float_is_float64` 归一化到 `float64` / `float32` 的合成 DefId
  （架构设计 §2.5 既定语义）。`double` 不做别名归一化（无文档依据，不发明语义）。
- **理由**：`TypeKind::Named` 的 `def` 字段必须有 DefId 可指，语料给不出 ⇒
  合成是唯一落点。与 D10「合成符号回落源头」同族，但基础类型是引擎内置、
  无源头声明 ⇒ `origin = None`。
- **波及**：`SYNTHETIC` 的 DefData **不进任何声明统计**（dump-index 对账口径
  与后续 workspaceSymbol 遍历同此纪律）；M1 对账数字不受影响。
- **落盘**：`as-core/src/index.rs`（`inject_builtins`）、LSP实现规划 §3.3。

### D26 M3 实现期三件定案（重索引粒度 / 收集规则 / 路径规范化）

- **背景**：M3 把 workspace 索引接进 server 时遇到三个规划未覆盖的实现细节。
- **裁决一（Ready 后编辑的重索引粒度）**：`didChange` 不做重活——语义请求
  （hover/definition）进来时检查该文件 overlay 版本是否领先于已索引版本，
  领先才走 `reindex_file`（§5.2 的**粗粒度 remove+re-add**：旧 DefId 遗留
  append-only arena 但从全部查询表摘除，不可达；闭包 / mixin 倒排全量重建，
  声明类型只重算该文件——441 文件量级毫秒）。惰性触发天然合并连击键，
  与 §6.1 冷启动「请求驱动」同一取向。**精确声明级 diff 与联动失效留 M4
  按需**（references/rename 才有跨文件失效刚需）。`didClose` 回落磁盘重读
  （§5.1）同样惰性执行。
- **裁决二（收集规则）**：任意收集根（scriptRoots ∪ typeDeclarationDirs，
  前者空 = 全部 workspaceFolders）下 `.d.as` 一律 Decl、其余 `.as` 一律
  Script，按规范化路径去重。理由：默认 `typeDeclarationDirs` 的
  `${workspaceFolder}/Saved/AS-Cache` 在「AS-Cache 目录本身是 workspace
  folder」的双根布局下展开后不存在，只有按扩展名分类才能命中——这是测试
  工作区（`test-as-lsp.code-workspace`）的实际形态。**多副本双源冲突仍按
  D24 搁置**（用户显式配置 typeDeclarationDirs 负责；AS0907 仍是预留码）。
- **裁决三（路径分隔符规范化）**：`Uri::to_file_path` 在 Windows 返回**正斜杠**
  形态，workspaceFolders / 配置根 / `read_dir` 拼接则可能混合 `/` 与 `\`——
  不统一会让 `intern_file` 给同一文件发两个 FileId（overlay 与索引彻底分裂，
  实测症状：hover 永远 miss）。裁决：**入 intern 前统一规范化**（Windows：
  `/` → `\`；收集侧与 `uri_path` 侧同规则），as-lsp `workspace::normalize_path`
  是唯一实现。
- **落盘**：as-lsp `workspace.rs`（`build_index` / `normalize_path` / 
  `WorkspaceState::ensure_file_fresh`）、LSP实现规划 §5.2（实现粒度注明）。

### D27 UseSite 落地形态与 references 匹配语义（M4 实现期定案）

- **背景**：规划 §4 把 UseSite / 引用倒排列为 Phase 2 产物、解析列为 Phase 3，
  但数据结构与匹配语义（尤其合成符号）未细化到可实现粒度。
- **裁决**：
  1. **记录**：`FileSnapshot.uses: Vec<UseSite>`（`(name, span, role)`，语法角色
     与 resolve 的 Role 对齐）+ 引用倒排 `ref_index: name → 文件集合`（BTree 保
     候选序稳定）。**不记录** primitive 使用点（内建无源码声明且 `float` 随配置
     归一化，不可 references/rename）、`named_argument` 名字标识符（形参引用，
     留 M5 与签名帮助同批——既定方针）、specifier 语境与 `access:Level` 的
     level 名；声明名（含 `for_each_statement` 迭代变量、namespace scoped_name
     尾段）排除。f-string 插值段是正常表达式子树，全树遍历天然纳入（架构设计
     §4.6 硬性要求，专项单测钉死）。
  2. **匹配语义**：站点解析集合 ∩ 查询集合 ≠ ∅ 即命中——**不可消歧的调用点
     对组内每个重载都算引用**（不可排除）；查询点本身消歧失败 ⇒ 对组内全部
     成员取并集（架构设计 §4.6「报全部重载」）。
  3. **DefId 不做 origin 归一**：D10 的回落只影响 definition/hover 的落点展示，
     不改变引用身份——合成成员（delegate 的 `Execute` / `StaticClass`）是独立
     名字，按各自 DefId 独立 references/rename。**唯一例外：class 的合成同名
     namespace 归一到类**（`AActor::` 限定段计入类引用——它就是类名本身）。
  4. **局部变量**：无 DefId，按 `(file, 声明 span)` 身份匹配（SemCtx 逐站点
     独立解析，遮蔽天然正确），引用天然限声明所在文件。
- **理由**：合成成员与其源头声明是两个名字，折叠会让「重命名委托类型」误改
  `Execute` 调用点；namespace 例外是「同名同物」——类名即命名空间名。
- **落盘**：as-core `uses.rs` / `references.rs`（模块头即语义约定）、
  LSP实现规划 §4.1（M4 落地形态）。

### D28 重载消歧分级 + rename 严格匹配（M4 实现期定案）

- **背景**：规划 §7.2 要求 references 消费重载消歧（失败报全部），但消歧的
  信息分级与 rename 的匹配口径未定。`expr_type` 完整定型（运算符 / f-string
  插值 / range-for 双跳）是 M5 signatureHelp 的前置，M4 全量推迟。
- **裁决**：
  1. **M4 消歧分级**：arity（`?` 通配形参不参与精确判定——引擎内部语法 §1.4）
     + **可定型实参的基类型比对**（数字/字符串/`n""`/布尔字面量、标识符、
     this、链式成员、调用返回、Cast——现有 `expr_type` 子集 + 字面量小扩展，
     数字后缀 / 进制 / 裸 float 宽度与 D25 同规则）。唯一命中 ⇒ 收敛单目标；
     否则保留整组。运算符 / f-string / range-for 实参定型随 M5。
  2. **消歧接入点在 `resolve_at` 内**（Callee / MemberProperty / ScopedLast 的
     调用语境）——hover / definition / references 共用同一结果（§7.2 消费方表
     的自然推论；M3 的 hover 多重载 fence 测试随之更新为双路径）。
  3. **rename 严格匹配**：只改「解析结果唯一且等于目标」的站点（歧义站点
     可能属于其它重载，改写会误伤——宁缺毋假，D14 同族）；
  4. **不可 rename 的目标**：重载组/歧义组（单查询一次只能改一个名字）、
     合成成员（origin 名 ≠ 自名，无独立源码声明——改名语义落到源头声明，
     用户应在那儿发起）、内建 primitive（无源码）。新名校验：identifier
     模式 + 保留字黑名单（grammar token 集实用子集），非法 → invalid_params。
- **落盘**：as-core `overload.rs::disambiguate`（排序判定）、`resolve.rs`
  （实参定型 + 接入点）、`references.rs::match_uses_strict`、as-lsp rename
  handler；LSP实现规划 v1.3 登记。

### D29 跨文件缓存失效：声明面指纹（M4 实现期定案，D26 遗留项落地）

- **背景**：D26 裁决一把「精确声明级 diff 与联动失效留 M4 按需」——references
  的按文件缓存引入后成为刚需：编辑文件 A 可能改变其它文件对 A 声明的解析结果
  （新增类成员 / 重载 / mixin），逐文件失效不够。
- **裁决**：reindex 前后对比该文件的「**声明面指纹**」——main 中属于该文件的
  `(名字, kind, 父名)` 有序集（含合成 namespace，函数体 / 局部 / 注释改动不变，
  对外可见声明增删改变之）：变了 ⇒ 整表失效解析缓存；没变 ⇒ 只失效该文件。
  精确「依赖该声明的文件集」失效留 M5+ 按需（先正确后优化——指纹对比是
  逐文件毫秒级，全量失效后的重解析全语料 <1s，见 D27 落地的性能数据）。
- **落盘**：as-core `index.rs::decl_surface`（`reindex_file` 返回值）、as-lsp
  `workspace.rs::reindex`（消费返回值决定失效面）。

### D30 workspaceSymbol 过滤规则（M4 实现期定案）

- **背景**：规划 §8.1 只写「主索引」，过滤集合未定。
- **裁决**：过滤 `SYNTHETIC`（D25 纪律：不进任何遍历统计）、不可达 DefId
  （append-only arena 的墓碑前残留——按 main 可达性过滤）、`LOCAL` 函数
  （模块私有；查询无文件语境无法按模块过滤 ⇒ **整体排除**，M4 定案）、
  声明文件已摘除（无快照）。匹配：大小写不敏感子串（客户端还会做自己的
  fuzzy 过滤）；结果封顶 2048（空查询全量喷发无消费场景且体积失控）。
- **落盘**：as-core `search.rs`；LSP实现规划 v1.3 登记。
