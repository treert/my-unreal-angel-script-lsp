## 1. 逐条记录

### D1 Rust 单测源码内置（用户拍板）

- **背景**：单测若读取 `tests/` 等外部 `.as` 文件，会引入文件系统依赖，破坏封闭性与可复现性。
- **裁决**：Rust 单元测试中的 `.as` 测试代码**一律内置于 Rust 源码**（字符串字面量），
  禁止读取外部文件。与 `ai-mylua-lsp` 同一约定。
- **注意点**：414 个 `.d.as` 不可能内置——它们的角色是 **as-cli 批量校验语料**（开发期验收
  动作，非 CI 单测；`Saved/` 目录可能被引擎清空，不构成稳定依赖）。复杂真实形态需要进单测时，
  **摘录片段内置**，而不是读文件。
- **落盘**：AGENTS.md「测试规则（硬性）」。

### D2 放弃旧 LSP golden 对账（用户拍板）

- **背景**：原计划用 Hazelight 旧 LSP 对同语料采 hover/definition 快照作回归基准，
  但旧 LSP 的类型真值依赖引擎在线（TCP 27099），采集自动化受限。
- **裁决**：不做 golden 对账。验收三支柱：

| 支柱 | 内容 |
|---|---|
| 单测 | as-core 纯库单测 + as-lsp 集成测试，源码内置（D1），固化**预期行为** |
| 语料批量 | as-cli 对 `Script-Examples` / `AS-Cache`（414 `.d.as`）/ 引擎 `Angelscript/**.as` 做 dump-tree/dump-index 校验 |
| 体感验收 | 每里程碑在 VSCode 扩展中人工验收（LSP实现规划 §9） |

- **理由**：语义真值已有引擎源码 + `as-docs` 取证体系兜底；无 golden 的回归风险用
  「单测固化预期」对冲。Hazelight 扩展降级为**纯人工参考**（不作为验收基准）。
- **落盘**：架构设计 §0.2 行为基准行、§6 P3/P4 验收、§7、§8 风险 5；LSP实现规划 §9/§10/§11/§12。

### D3 crate 命名 `as-syntax`

- 441 文件 rayon 并行 parse 是秒级开销，不值得为「无函数体轻扫」维护第二套扫描口径。

- Phase 2 只记录引用使用点 `(name, range, 语法角色)`，解析放 Phase 3 请求驱动 + 按文件缓存。

  （可 `$/progress`），属可接受代价。详见 LSP实现规划 §4.1。

### D8 `unresolved_object` 语义（Q3，取证完成）

- **是什么**：类型名的标记后缀，由 C++ 绑定层 `FObjectPtrType` 在**成员变量声明模式**下生成
  （`[UE]Private/Binds/Bind_BlueprintType.cpp:1854-1872`，`IsUnresolvedObjectPointer()` 标记，
  告知 AS 编译器按 TObjectPtr 解析）；语料如 `Bind_FLatentActionInfo.cpp:23` 的
  `"UObject unresolved_object CallbackTarget"`。脚本作者不书写它。
- **裁决**：TypeRef **不设新变体**——语法层记 flag；推导、成员补全、重载匹配一律按**基类型**
  （如 `UObject`）处理；hover/签名原样渲染后缀。完整约定见
  [`架构设计-引擎内部语法.md`](架构设计-引擎内部语法.md) §3（本次新增）。
- **诊断预留**：用户 `.as` 中出现该后缀属异常形态，P5 占号归 `AS09xx`（引擎无对应报错，
  非引擎行为复刻）。

### D12 `FileId` 注册表（路径 intern）

- **背景**：mylua 的 `UriId`（`uri_id.rs`）把脚本路径转成 int id。讨论焦点：441 文件量级是否值得第一天就上。
- **裁决**：**第一天就用**。它是**接口不变量**而非热点优化——`FileId` 是 ID 体系四键之一，
  `DefData.file`、`UseSite`、per-file 缓存表全部以它为键，后补 = 全量签名改动。
- **适配**：根序优先级替换 mylua 的 annotation 启发式；路径 intern 下沉 as-core
  （去掉 tower `Uri` 依赖）；容量缩配。
- **详见**：[`实现优化.md`](实现优化.md) §1（**本文件不重复展开，统一引用该文档**）。

### D13 `Sym`（符号 intern）

- **背景**：mylua 的 `LuaSymbol`（`lua_symbol.rs`，lasso `ThreadedRodeo`）。
- **裁决**：**第一天就用**。动机排序：一致性 > 内存去重 > 性能。as-core 纯库边界修正为
  「无 IO、无 async、允许只增 intern 表」。
- **详见**：[`实现优化.md`](实现优化.md) §2。

### D14 `auto` 推导链：表达式定型管线（含 range-for 协议取证）

- **背景**：`auto location = this.GetActorTransform().GetLocation();` 一例揭示：占位表示
  （`TypeKind::Auto`）已定，但推导链——`this` 定型、链式成员访问、range-for 元素类型——
  需要明确设计，且 hover/补全/重载排序依赖同一原语。
- **裁决**：Phase 3 以 `expr_type` 单一原语承载（自底向上 + per-file 缓存）；range-for
  元素类型按引擎 `Iterator()/Iterate()` 双跳协议（`[ENGINE]as_compiler.cpp:5745-5873` 取证，
  新迭代器模式默认，旧模式不建模）；推导失败降级**宁缺毋假**（hover 原样、补全不出）。
- **候选诊断**：`Range-based for value is not iterable`（引擎原文 `as_compiler.cpp:5836`），
  P5 占号时归段待定，先不占号（码表纪律）。
- **解析时机澄清**：扫描阶段（Phase 1/2）完全不碰表达式定型——auto 只允许局部变量与
  range-for，字段/形参/返回值/全局变量一律显式，持久索引中 auto 只是占位记录。
  解析只发生在请求驱动场景（inlay hints、hover、补全、诊断 = 打开的文件；
  references/rename 消歧触达未打开文件时也是惰性 + 缓存）。auto 推导是函数体局部
  自包含分析，无需流敏感。
- **详见**：LSP实现规划 §4.2。

### D15 `.d.as` 注解标签白名单 + tag/doc 分流

- **背景**：2026-09 对账 414 个实际 `.d.as` 与 `TypeDeclarationExporter.cpp`，发现早期设计稿
  （架构设计 §2.4 旧版）与产出物严重脱节：设计的文件头 4 个 tag（`@engine` / `@plugin` /
  `@floatIsFloat64` / `@exported`）**一个都不存在**；实际最高频的 `@editable`（12917 次）
  与 `@cache_format` / `@group` / `@notProperty` **完全未被文档收录**。同时透传的 C++ 注释里
  混有 doxygen tag（`@param` 6406 次、`@see` 460 次…）与任意标识符 tag（`@Indices`、
  `@bInLocked`、`@InFrameNumber`），且与语义 tag **紧邻同块出现**。
- **裁决**：
  1. 语义 tag 采**白名单**（架构设计 §2.4.3 的 15 项，含 4 项语料零出现但导出器已实现的）；
  2. 白名单外一律作 doc 正文；doxygen 常见 8 个 tag 在 hover 渲染为 markdown 结构，其余原样；
  3. **未登记 tag 忽略且不报诊断**——引擎注释噪声无法穷举；
  4. 语义 tag 的 value 解析失败即丢弃该 tag，不报诊断（数据源机器生成，出错是导出器 bug）。
- **理由**：数据源是机器生成且**不受本仓控制**，唯一稳健策略是白名单 + 静默降级。
  黑名单或「报未知 tag」都会随引擎注释变动而刷屏。
- **落盘**：架构设计 §2.4.3（全表 + 源码行号）、§2.4.4（分流规则）；
  LSP实现规划 §2.2（`decl_tags.rs`）、§3.2（`DefFlags`）、§9 M1 验收。

### D16 struct 单层查找 + 属性访问器反向默认

- **背景**：两处「反直觉但有取证」的语义，早期文档均写错或未写。
- **裁决一（struct 单层）**：继承闭包**只对 class 建**，struct 成员查找单层。
  取证：① `.d.as` 的继承输出经 `ASType->GetClass()->GetSuperClass()`，struct（UScriptStruct 支撑）
  走不到该分支，**导出物里 struct 永远没有父类**（`TypeDeclarationExporter.cpp:535-554`）；
  ② C++ USTRUCT 继承在绑定层用 `TFieldIterator` **已展平**成自有成员
  （`as-docs/struct类型专题.md` §6.3）。为 struct 建闭包是无效工作，且会掩盖「展平」事实。
- **裁决二（访问器反向默认）**：引擎配置 `bAllowImplicitPropertyAccessors = true`，
  **绑定函数默认全部是属性访问器**，导出器只在 `IsProperty()` 为 **false** 时写出
  `@notProperty`（`:218-224`，该处注释即权威说明）。
  → 查找链第 3 级必须按「**默认是候选，带 `NOT_PROPERTY` 的除外**」实现。
  反着做（默认不是、见 tag 才是）会让 `Actor.BaseValue` 这类访问全部失效。
  另一半工作导出期已完成：`asTRAIT_GENERATED_FUNCTION` 的 `Get*/Set*` 已被转写成属性声明
  （`:434-469`），LSP 不需再配对。
- **附带**：查找链同时补入 `this`/`super`（第 0 级）、mixin 伪成员（第 4 级，按首参类型倒排）、
  `local` 函数模块隔离——原五级链缺这三项的**落地表示**，只有约束描述。
- **落盘**：架构设计 §2.4.2、§2.4.5、§4.5（0-6 级表）；LSP实现规划 §4（Phase 2 产物）、§7.1。

### D17 `TextRange` 字节偏移 + 类型规范形式

- **背景**：① 原 `DefData.name_range: Range` 与 `range.rs`（UTF-16 换算）混用，
  与「as-core 不依赖 LSP 协议类型」的纯库边界冲突；② `const T&` 可表示为
  `Const(Ref(T))` 或 `Ref(Const(T))`，两者结构不相等 ⇒ 同一类型拿到两个 TypeId。
- **裁决**：
  1. as-core 内部一律 `TextRange = (u32, u32)` **字节偏移**；行列换算只在 as-lsp 边界发生；
     **行首偏移表**（每文件 `Vec<u32>`）列为 Phase 2 持久产物，否则每次换算 O(文件长度)；
  2. 类型修饰符强制规范顺序 `Ref → Const → Array → Named/Param/Wildcard/Auto`，
     只能经 `intern_type()` 构造（内部重排 + 折叠 `Const(Const(T))`），字面量构造私有化。
- **理由**：两条都属 **接口不变量**，适用 D12 立下的判据（「接口不变量类优化必须第一天就上」）。
  规范形式是「TypeId 相等即同一」的唯一保护，破了它整个类型系统的去重与缓存键都失效。
- **落盘**：LSP实现规划 §3.2.1、§3.3、§4（Phase 2 产物）、§8、§12 G7。

### D18 overlay 唯一真值 + 文件生命周期 + 冷启动重放

- **背景**：原 §5 只写了「didChange 后怎么失效」，缺三块必备机制：
  ① 未保存缓冲与磁盘内容的优先级；② `.as` 增删改名；③ 冷启动快照发布前到达的编辑。
- **裁决**：
  1. **overlay 唯一真值**：`didOpen` 后文本来自 overlay，`didClose` 回落磁盘并重读；
     `didSave` 不触发重读；文件监视事件命中有 overlay 的文件则忽略；
  2. **文件生命周期**：`.as` 增/删/改名分别处理（改名 = 删+增，因模块名随路径变、
     影响 `local` 可见域）；`.d.as` 任一变化 → 整目录重建，且必须 **500ms 防抖**
     （导出器会先清空目录再写 414 文件，客户端瞬间推来上千事件）；
  3. **FileId 墓碑**：注册表 append-only，删除只打 `alive = false`，不回收 id；
     同路径重现则复用并翻回 `alive`；遍历型查询必须过滤 `!alive`；
  4. **冷启动重放**：`Loading` 期间编辑照常写 overlay 并记入 `pending_dirty`，
     快照 `arc-swap` 换根后立刻用 overlay 重放该集合，再置 `Ready`。
     非语义请求（documentSymbol / folding / semanticTokens）在 Loading 期即可服务。
- **理由**：overlay 独立于索引存储，是「编辑永不丢」的根本；有了它，冷启动竞态只需
  「发布后重放一次」这一个动作，无需复杂的事件排队与版本对齐。
- **落盘**：LSP实现规划 §5.1/§5.2/§5.3、§6.1、§8、§9 M4、§12 G8；实现优化 §1.4（墓碑）。

### D19 `.d.as` 与 `.as` 是交叉关系（非子集）；模板声明头定性

- **背景**：`Core.d.as:646` 的 `struct TArray<T> { ... }` 引出「引擎是否支持脚本定义模板」的追问。
  取证结论是**不支持**，且顺带发现两处文档表述错误
  （`grammar/README.md` 与架构设计 §3 都写「`.d.as` 是 `.as` 的**子集**」）。
- **裁决一（模板定性）**：AS 有**两条互不相通的解析入口**——
  脚本走 `ParseScript → ParseClass`（`[ENGINE]as_parser.cpp:3734`，标识符后只接受
  `;`/`:`/`{`，**不认 `<`**）；模板声明头走 `ParseTemplateDecl`（`:176`，标识符后**必须**是
  `<`，且须以 `ttEnd` 收尾、**不认类体**），后者只被
  `asCScriptEngine::RegisterObjectType`（`as_scriptengine.cpp:1719`）调用。
  第三道锁：UE 预处理器类名正则不含 `<>`（`AngelscriptPreprocessor.cpp:723`）。
  ⇒ **脚本侧不能定义模板**（class/struct/函数皆不可），`.d.as` 里的 `struct TArray<T>`
  是**我们导出器渲染的文本**（`TypeDeclarationExporter.cpp:526-533`），引擎从不读 `.d.as`。
  该完整形态（声明头 + 类体）在引擎任何入口下都非法，**只在本项目的 `.d.as` 方言里合法**。
- **裁决二（关系修正）**：`.d.as` **不是** `.as` 的子集，而是与之**交叉**。
  `.d.as` 独有 4 项（`type_parameters` / `?` / `unresolved_object` / `@templateSpecialization` 块），
  `.as` 独有函数体、语句、delegate/event/asset、mixin/local、局部 `auto`、f-string 等。
  **两个后果**：① 反向推理不成立 ⇒ `.as` 中误写 `.d.as` 独有构造必须报语义诊断
  （码表 §7.1 新增两条待占号）；② **验收口径必须分开算**，一侧零 ERROR 不替另一侧背书。
- **裁决三（特化块消歧）**：实测 `struct TArray<T>` / `struct TMap<K,V>` /
  `class TSubclassOf<T>` / `class TArray<FVector>` 四形态**全部零 ERROR，文法无需改动**
  （关闭架构设计 §8 风险 9）。`type_parameter` 节点同时承载类型形参与具体实参，
  语义层按「声明前是否有 `@templateSpecialization` tag」消歧，不新增文法规则。
- **实现推论**：`TypeKind::Param` **只可能来自 `.d.as`**，`.as` 索引路径可直接断言其不出现；
  模板实例化输入恒为「`.d.as` 定义 + `.as` 侧具体实参」。
- **落盘**：架构设计 §3、§8 风险 9（关闭）/风险 10（新增）；
  引擎内部语法 §4（新增）+ §5（四件套总览）；`grammar/README.md`（新增「交叉非子集」节、
  偏差 §4 更新、语义合法性表 +2 行）；`as-docs/设计取舍与使用限制.md` §2.5.1（语言真值）；
  诊断码表 §7.1。

### D20 LSP 不读 `_manifest.dctx`；`floatIsFloat64` 转配置项（用户拍板）

- **背景**：D15 对账时把 manifest 定为「失效校验 + `float_is_float64` 数据源」，设计了四级校验链。
  复盘时用户指出：**LSP 的类型真值来源就该只有 `.as` / `.d.as` 源码**（§0.2 原始目标），
  读第二种文件格式是架构上的多余路径。
- **裁决**：
  1. **运行时完全不读 `_manifest.dctx`**，删除 `manifest.rs`；as-core 只认一种输入——源码文本；
  2. `float_is_float64` → **LSP 配置项** `floatIsFloat64: boolean`，默认 `true`
     （对齐引擎 `bScriptFloatIsFloat64` 默认值），在 vscode-extension 侧配置；
     **取消原 `"auto"` 三态**（其语义是「读 manifest」，数据源已不存在）；
  3. 格式版本 → 读 **`.d.as` 文件头的 `@cache_format` tag**，不设配置项。
     它与 manifest 首行 `AS_TYPE_CACHE v1` 同源，且已在白名单 tag 表内（架构设计 §2.4.3）
     ⇒ LSP 解析 `.d.as` 时顺带取得，既不需要额外文件，也不该让用户去填这种技术细节；
  4. `engine_version` / `exported_utc` / `files=` **忽略**；`type_count` / `member_count`
     降级为**开发期人工对账参照**（M1 验收），非运行时依赖。
- **为什么 `float_is_float64` 不能一起丢**（取证）：它不是元数据，而是**语义输入**——
  `.d.as` 里的浮点是原样透传的引擎类型名，**无法自证宽度**：

  | token | 语料出现 | 含义 |
  |---|---|---|
  | `float32` | 8589 | 显式单精度 |
  | 裸 `float` | 1825 | 宽度由引擎设置决定 |
  | `float64` | 2（均在注释） | ⇒ 导出器从不展开宽度 |

  决定性对比：`struct FVector { float X; }` 与 `struct FVector3f { float32 X; }`
  并存于 `Core.d.as`。引擎开关 `bScriptFloatIsFloat64 = true` 是 `UPROPERTY(Config)`，
  **可被项目 ini 覆盖**（`[UE]Public/AngelscriptSettings.h:159-161`），故不能硬编码。
- **代价（已接受）**：
  - `AS0901`（指纹过期）retired——指纹校验对正确性无影响，且 manifest 本无插件指纹，
    最常见的「改绑定不改引擎版本」本就检测不到；
  - `AS0905`（group 文件名冲突）retired——唯一数据源是 `files=` 列表，磁盘上无从判断
    丢了哪些 group。该缺陷归导出器侧修（架构设计 §8 风险 7），用户侧会遇到
    「少数模块类型找不到且无提示」；
  - 新增风险：`floatIsFloat64` 配错是**静默错误**（架构设计 §8 风险 11 / 规划 §12 G9），
    缓解靠默认值对齐 + 状态栏常显生效值 + M1 双取值用例，不设诊断（无法自动检出）。
- **新增码**：`AS0906`（`@cache_format` 高于支持版本，仍尽力解析不阻断）。
- **落盘**：架构设计 §2.4.1/§2.5/§5/§8（风险 6 关闭、7 修订、11 新增）/§9；
  LSP实现规划 §2.2（删 `manifest.rs`）/§3.3/§5.3/§8.1/§9 M1·M6/§12（G6 修订、G9 新增）；
  诊断码表 §7（`AS0901`/`AS0905` retired、`AS0902` 改、`AS0906` 新增）/§8/§10。
