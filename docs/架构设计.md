## 0. 背景与目标

### 0.1 现状问题

Hazelight 的 `vscode-unreal-angelscript` LSP 存在结构性缺陷：

- **类型真值来源是运行时引擎**（TCP 27099 的 DebugDatabase），引擎不启动时 hover/定义/引用全部失效；
- 解析器是 Peggy/PEG + 手写语句切片，容错设计服务于"逐语句增量"，难以现代化；
- LSP（Node.js）单线程，大项目解析队列会阻塞事件循环。

### 0.2 目标

**类型真值来源 = `.as` 源码 + `.d.as` 导出声明文件**，引擎连接降级为可选增强：

| 功能 | 数据来源 | 是否需要引擎在线 |
|---|---|---|
| hover / 定义跳转 / 引用 / 补全 / 重命名 | `.as` + `.d.as` | 否 |
| semantic tokens / 文档符号 / 折叠 | tree-sitter CST | 否 |
| 诊断 | **LSP 自有规则**（`.as` + `.d.as`） | 否（D22） |
| 调试（DAP）/ 资产名补全 / 跳 C++ 源码 | 引擎 | 是 |

> **诊断方针（D22）**：诊断由 LSP **自主设计、按需实现**，不以「复刻引擎报错」为目标，
> 也不依赖引擎 Diagnostics 透传。引擎在线通道（P6）若接入，诊断只是可选叠加项。
> 已取证的引擎约束见 [`诊断码表.md`](诊断码表.md) §2——那是**素材库**，不是实现清单。

### 0.3 与 mylua-lsp 的复杂度对比

AS 是强类型语言，`.d.as` 是机器生成的规范声明——相比 mylua-lsp 需要处理的弱类型 + EmmyLua 注释随意性，**类型索引层大幅简化**：

- 无需猜类型（emmytype 的 `@param` 可能缺失/冲突/过时）；
- 声明是穷尽的（引擎反射全量导出），无需启发式回退；
- 泛型是编译期单态化（无协变推导、无特化匹配），实例化是纯查表+克隆。

## 1. 总体架构

```
+-----------------------------------------------------------------------+
|                    模块一：UE 导出插件（C++，Editor DLL）               |
|   菜单命令 → 遍历 AS 引擎注册类型 → 生成 .d.as → <Project>/Saved/AS-Cache |
+------------------------------------+----------------------------------+
                                     |  .d.as 声明文件（按 UE 模块分文件）
                                     v
+-----------------------------------------------------------------------+
|              模块三：LSP 核心层（Rust，独立 crate）                     |
|  tree-sitter 解析(.as/.d.as) → 符号索引 → 类型推导 → LSP 响应           |
+------------------------------------^----------------------------------+
                                     |  JSON-RPC (stdio)
                                     v
+-----------------------------------------------------------------------+
|              模块四：VSCode 扩展（TypeScript）                          |
|  客户端启动/配置/命令 + （远期）DAP 透传                                 |
+-----------------------------------------------------------------------+

模块二（tree-sitter grammar）被模块三内嵌使用，不是独立进程。
```

技术栈对齐 mylua-lsp：tree-sitter（语法）+ Rust（核心，含 LSP 服务）+ TypeScript（扩展宿主）。

## 2. 模块一：UE 导出插件

### 2.1 形态与入口

- **项目 Editor 插件**（如 `Demo_AS/Plugins/AngelscriptTypeExporter`，或放 `Source/` 下随项目编译），依赖 `AngelscriptCode` 模块；
- 入口：编辑器菜单 `Tools > Angelscript > Export Type Declarations (.d.as)`，同步命令（导出耗时秒级，带 SlowTask 进度）。

### 2.2 数据源与过滤

数据源与 `FAngelscriptDebugServer::SendDebugDatabase` 相同：遍历 `FAngelscriptManager::Get().Engine` 的全部注册类型 + 全局函数/枚举/属性，**但过滤掉脚本类型**：

```cpp
// 伪代码
for (each ObjectType)
    if (Type->GetFlags() & asOBJ_SCRIPT_OBJECT) continue;   // 脚本类由 LSP 解析 .as 获得
    if (TypeName.IsEmpty() || TypeName[0] == '_') continue;  // 内部类型
    ExportType(Type);
```

脚本类型（`asOBJ_SCRIPT_OBJECT`）**不导出**——它们能从 `.as` 源码完全推导，导出只会造成双源冲突。
`asOBJ_FUNCDEF` 同样跳过（delegate 由 `.as` 源码展开，见 §4.4）。

**逐条过滤规则**（真值 = `TypeDeclarationExporter.cpp`，LSP 侧不得假设语料里存在被过滤的形态）：

| 层级 | 跳过条件 | 源码位置 |
|---|---|---|
| 类型 | 空名 / `_` 前缀 / `asOBJ_SCRIPT_OBJECT` / `asOBJ_FUNCDEF` | `:360-367` |
| 属性 | `isDeprecated`（仅 `WITH_EDITOR`） | `:391-392` |
| 方法 | `asTRAIT_DEPRECATED`、`__` 前缀名 | `:431`、`:160` |
| 形参 | `__` 前缀名、`hiddenArgumentIndex` 位 | `:252`、`:241` |
| 全局 | `asTRAIT_DEPRECATED` 函数、`_` 前缀变量 | `:641`、`:715` |
| 函数整体 | 任一形参 `TypeId == -1`（无法表达，整函数丢弃） | `:262-263` |

### 2.2.1 分组规则（已定，取代原「待调研」）

分组依据已实现并验证，**方案 (b)**：

| 内容 | group 取法 | 落盘文件名 |
|---|---|---|
| class / struct / enum | 所属 `UPackage->GetName()`，如 `/Script/Engine`；取不到 → `Core` | 末段，`Engine.d.as` |
| 模板特化函数块 | 同上 | 同上 |
| namespace | 若 namespace 名恰是某个类型名（组件访问器 namespace）→ 该类型的 UPackage；否则 namespace 自身名 | `::` → `.`，如 `Math.d.as` |
| 无 namespace 的全局函数/变量 | 固定 `Global` | `Global.d.as` |

取证：`ResolveClassGroup`（`:94-113`）、`ResolveNamespaceGroup`（`:121-139`）、`MakeGroupFileName`（`:82-91`）。

**推论（LSP 侧必须接受的事实）**：

1. **一个逻辑类型的声明会跨文件**。`struct FVector` 在 `Core.d.as:10103`，而 `namespace FVector`（`ZeroVector` 等常量）在 `FVector.d.as`。
   → `definition` 对 `FVector` 有两个合法落点（类型 / 同名命名空间），按查找链语境（`FVector v` vs `FVector::ZeroVector`）择一，见 §4.5。
2. **`@group` 有两种形态**：`/Script/Xxx` 包路径 与裸绑定名（`Math` / `Array` / `FVector` / `Global`）。
   workspaceSymbol 的 container、hover 的归属显示统一取**末段**（与文件名一致），不做两套渲染。
3. **文件名冲突会丢数据**（见 §8 风险 7）：group key 不同但末段相同时（`/Script/Slate` 与 namespace `Slate`）后写覆盖先写。
   实测 434 个 group → 414 个文件，**20 个 group 内容丢失**。
   唯一可检出处是 manifest 的 `files=` 重复项，但 **LSP 不读 manifest**（§2.5 / D20）
   ⇒ 该缺陷在 LSP 侧**不可见也不报告**，只能在导出器修（§8 风险 7）。

### 2.4 `.d.as` 文件格式

**核心决策：`.d.as` 使用 AngelScript 自身语法**（无函数体的声明），不发明独立 DSL。语法上就是 BNF 中 `function_decl ::= ... ( ';' | statement_block )` 取 `';'` 分支、类成员取声明子集。

> **本节是按实际导出物校订的真值**（2026-09 对账 414 个 `.d.as` + `TypeDeclarationExporter.cpp` 逐行核对）。
> 行号引用均指该文件。**LSP 实现以本节为准**，不得沿用早期设计稿的 tag 名。

#### 2.4.1 文件头（固定 4 行）

```angelscript
// ==== AngelscriptTypeDeclarations ====
// @cache_format 1
// @group /Script/Engine
// Generated by AngelscriptTypeExporter - do not edit.
```

`:777-780`。**注意**：引擎版本、`float_is_float64`、导出时间**都不在文件头**，只在
`_manifest.dctx` 里——而后者 LSP 不读（§2.5），`float_is_float64` 改由配置项提供。

**`@cache_format` 不做任何版本校验**（决策 D21）：识别该 tag（避免被当作 doc 文本混进
hover），但**不消费其值**。理由——`.d.as` 是**源码而非协议**，源码不需要版本协商；
且 §2.4.4 的「白名单 + 未登记 tag 静默忽略」规则本身已是**版本无关**的：

| 导出器未来的变更 | 旧 LSP 行为 | 需要版本号 |
|---|---|---|
| 新增 / 改名 / 删除 tag | 白名单外 → 忽略；查不到 → 走默认值 | ❌ 优雅降级 |
| 语法结构变更 | tree-sitter 报 ERROR，走解析诊断 | ❌ 已覆盖 |
| 语义极性反转（如 `@notProperty` → `@isProperty`） | 静默错误 | **版本号也救不了**（只能说「不匹配」，说不出「怎么解释」） |

加之导出器是本项目自有代码（非第三方独立演进），格式变更与 LSP 改动同批发生，
开发期即暴露。⇒ 版本校验无消费场景，`AS0906` 随之 retired。

#### 2.4.2 声明形态

```angelscript
struct FVector          // asOBJ_VALUE → struct；否则 class（:519-522）
{
    float64 X;
    protected float64 W;                       // protected 属性前缀（:399-400）
    float64 Dot(const FVector&in Other) const;
    FVector(float64 InX, float64 InY);         // 构造/工厂 → 构造声明（:480-513）
}

// @template_covariant
class TArray<T>                                // 模板形参列表（:526-533）
{
    int Num() const;
}

// @templateSpecialization
class TArray<FVector>                          // 特化块：实参是具体类型（:617-618）
{
    void SortByLength();
}

class AActor : UObject                         // 继承：仅 class，见下方警告（:535-554）
{
    // Returns the location of the actor.
    // @ufunction
    // @unrealname K2_GetActorLocation
    FVector GetActorLocation() const;
}

enum EAutoReceiveInput { Disabled = 0, Player0 = 1, }   // 值带 `= N`，尾随逗号（:695）

namespace Math { float64 Sqrt(float64 Value); }

// Global functions and variables (no namespace)
void Print(const FString&in Message);          // 无 namespace → 裸声明 + 该注释（:747）
```

**继承输出只对 class 生效**：`:535-554` 经 `ASType->GetClass()` 拿 `UClass` 再取 `GetSuperClass()`，
struct（UScriptStruct 支撑）走不到该分支，**`.d.as` 里的 struct 永远没有父类**。
这与 `as-docs/struct类型专题.md` §6.3 的「绑定层已展平、成员查找单层」互为印证 → 语义层约定见 §4.5。

`// @tag [value]` 置于声明前，与 doc 注释行混排（doc 在前、tag 在后，`:307-308`）。

#### 2.4.4 tag 与 doc 注释的分流规则（LSP 侧强制）

透传的 C++ 注释里含大量 doxygen tag 与任意标识符 tag，实测语料除上表外还有：
`@param`(6406) `@return`(1344) `@see`(460) `@note`(325) `@todo`(50) `@returns`(31)
`@warning`(20) `@brief`(9) `@out` `@code/@endcode` `@example`，以及**参数名 tag**
（`@Indices` `@bInLocked` `@InFrameNumber` `@DeleteIndex`…）。且两类会紧邻出现：

```angelscript
    // @see bGenerateOverlapEventsDuringLevelStreaming, ...
    // @editable
    EActorUpdateOverlapsMethod UpdateOverlapsMethodDuringLevelStreaming;
```

规则（决策 D15）：

1. **白名单驱动**：只有 §2.4.3 表中的 tag 被当作**语义 tag**（进 `DefData`，不进 doc 文本）；
2. 其余一律视为 **doc 正文**，原样保留。其中 doxygen 常见 tag
   （`@param` / `@return` / `@returns` / `@see` / `@note` / `@warning` / `@brief` / `@todo`）
   在 hover 里渲染成 markdown 结构（`@param X Y` → 参数列表项），其他原样输出；
3. **未登记 tag 一律忽略，不报诊断**——引擎注释噪声无法穷举，报错只会刷屏；
4. 语义 tag 的 value 解析失败（如 `@outputTypeIndex abc`）→ 丢弃该 tag，不报诊断（数据源是机器生成，
   出错说明导出器有 bug，不是用户问题）。

#### 2.4.5 属性访问器：反向默认（关键，易错）

导出器 `:218-224` 的注释是权威说明：引擎配置 `bAllowImplicitPropertyAccessors = true`，
**绑定函数默认全部是属性访问器**，因此 flag 只在**为 false 时**才写出 `@notProperty`。

→ LSP 的查找链第 3 级（§4.5）必须按「**默认是访问器，除非带 `@notProperty`**」实现。
反着做（默认不是、见 tag 才是）会让 `Actor.BaseValue` 这类访问全部失效。

另一半在导出期已完成：C++ 侧**自动生成**的 `Get*`/`Set*` 访问器
（`asTRAIT_GENERATED_FUNCTION`）已被导出器直接转写成**属性声明**（`:434-469`），
与手写属性同名时去重（`DocumentedProperties`）。这部分不需要 LSP 再做配对。

#### 2.4.6 签名细节（影响 signatureHelp / 命名实参补全）

| 现象 | 说明 | 源码 |
|---|---|---|
| 形参名 `InArg0` / `InArg1` | 引擎侧**该参数无名**时的占位名 | `:64-68` |
| `const T&in` | 仅当 `(INREF\|CONST)` 且**宿主类型非模板**时补 `&in`；其余 const 引用**丢 `&`** | `:268-269`、`:51-59` |
| `&` / `&out` / `&in` | 仅非 const 时保留方向 | `:51-59` |
| `? Name` | 通配形参，丢弃 `&` 与方向（见[引擎内部语法](架构设计-引擎内部语法.md) §1.2） | `:256-259` |
| blueprint event 的 `float32` 值参 → `float` | 事件签名固定 float32，调用侧自动扩展 | `:271-277` |
| 默认值 | `Type Name = Expr` 原样透传引擎串 | `:280-285` |

**`InArgN` 是占位而非真名** → 命名实参补全（`f(Name: value)`）**不得**提供 `InArgN`，
否则补出来的代码在引擎侧必然编译失败。索引期给这类形参打 `unnamed` 标记。

### 2.5 `_manifest.dctx`：**LSP 不读**（决策 D20）

导出器会写一个清单文件，实测内容（`TypeDeclarationExporter.cpp:762-794`）：

```
AS_TYPE_CACHE v1
engine_version=5.8.3-0+UE5
float_is_float64=true
exported_utc=2026.09.26-14.40.33
type_count=14864
member_count=69337
files=ACLPlugin.d.as,ActorLayerUtilities.d.as,...
```

**裁决：LSP 运行时完全不读此文件。** 类型真值来源严格限定为 `.as` + `.d.as` **源码**
（§0.2 的原始目标），不引入第二种文件格式与第二条解析路径。

进一步（D21）：**连格式版本也不校验**——LSP 对 `.d.as` 的态度就是「当作 AngelScript
源码来读」，读得懂多少算多少，不做任何版本协商。唯一从 manifest 迁出的语义信息是
`float_is_float64`（→ 配置项）。

逐字段处置：

| 字段 | 处置 | 理由 |
|---|---|---|
| `float_is_float64` | → **LSP 配置项**（§5） | 语义必需，但 `.d.as` **无法自证**（见下），只能由用户/工作区声明 |
| `AS_TYPE_CACHE v<N>` | **忽略** | 版本校验无消费场景（D21）：`.d.as` 是源码非协议，且 tag 白名单规则本身版本无关。文件头的 `@cache_format` 同样只识别、不消费（§2.4.1） |
| `engine_version` / `exported_utc` | **忽略** | 指纹校验对功能正确性无影响：声明过期了内容依然自洽，只是少几个新 API。`AS0901` 随之 retired |
| `files=` | **忽略** | 唯一用途是检出 group 文件名冲突（§2.2.1 推论 3），失去该数据源后 `AS0905` retired——那本是导出器缺陷，应在导出侧修，不该由 LSP 兜 |
| `type_count` / `member_count` | 运行时忽略 | 仅作 M1 的**人工对账参照**（开发期 as-cli 动作，非运行时依赖），见 [`LSP实现规划.md`](LSP实现规划.md) §9 M1 |

#### 为什么 `float_is_float64` 必须外部声明

`.d.as` 里的浮点类型**不是**具体宽度，而是原样透传引擎类型名。实测语料：

| token | 出现 | 含义 |
|---|---|---|
| `float32` | 8589 | 显式单精度（blueprint event 形参、`FVector3f` 等） |
| 裸 `float` | 1825 | **宽度由引擎设置决定** |
| `float64` | 2（且均在注释里） | ⇒ 导出器**从不**把 `float` 展开为具体宽度 |

决定性对比（同一文件内并存）：

```angelscript
struct FVector   { float   X; float   Y; float   Z; ... }   // Core.d.as:10103
struct FVector3f { float32 X; float32 Y; float32 Z; ... }
```

引擎侧开关（`[UE]Public/AngelscriptSettings.h:159-161`）：

```cpp
/* In order to avoid confusion with blueprints, make the 'float' type in script resolve to 'float64'. */
UPROPERTY(Config, EditDefaultsOnly, Meta = (ConfigRestartRequired = true))
bool bScriptFloatIsFloat64 = true;
```

默认 `true`，但 `UPROPERTY(Config)` ⇒ **可被项目 ini 覆盖**，因此不能在 LSP 侧硬编码。
配错的后果：`FVector.X` 的 hover 宽度、`auto` 推导、`opMul(float)` 与 `opMul(float32)` 的
重载匹配、字面量 `1.5` / `1.5f` 定型全部偏差，且**无任何报错**（静默错误）。
→ 配置项必须在扩展 README 与配置描述里显著说明其与引擎设置的对应关系。

## 3. 模块二：tree-sitter 语法解析（**已完成**，见 `grammar/README.md`）

- `grammar/grammar.js` 按 `grammar/angelscript.bnf` 实现（该 BNF 已含 tree-sitter 实现注记：优先级表 §5.5、节点命名表 §5.6、冲突清单 §5.4）；BNF 文件已随文法一起移入 `grammar/`；
- **外部 scanner（scanner.c）只保留 format string**：`format_string_content`（逐字保留文本/空格/`{{`转义）+ `format_spec`；heredoc `"""..."""`、`n"..."`、preproc 行用普通 token 即可；`>>` 无需拆分（模板实参位置不接受移位运算，词法状态自然切分）；
- **实际声明的冲突**（grammar.js `conflicts:`，对应 BNF §5.4）只有 4 组：`type`/`_expression`、`parameter_list`/`argument_list`、`template_type`/`_expression`、`named_argument`/`_expression`(`/type`)；classic-for vs range-for、函数声明 vs 变量声明由这几组加动态优先级导出；
- 命名实参同时支持 `:` 与 `=`（引擎设置 `asEP_ALTER_SYNTAX_NAMED_ARGS = 1`）；
- 错误恢复：BNF §3.7 的 [lsp] 容错产生式**不做成具名规则**，交给 tree-sitter 内建恢复 + 查询侧容错，关键中途编辑形态在 `test/corpus/error_recovery.txt` 固定快照；
- `.d.as` 与 `.as` 用**同一 parser**，按文件后缀/目录区分模块性质。
  **但两者的语法集合是交叉关系，不是子集**：`.d.as` 独有 `type_parameters`（模板声明头）、
  `?`、`unresolved_object`、`@templateSpecialization` 块——这四项在 `.as` 中一律非法
  （引擎侧 parse error 或绑定层专属）；`.as` 独有函数体/语句/delegate/event/asset/
  mixin/local/局部 `auto`/f-string。详见 [`grammar/README.md`](../grammar/README.md#as-与-das-的关系交叉不是子集)
  与 [`架构设计-引擎内部语法.md`](架构设计-引擎内部语法.md) §5。
  **推论**：两侧验收口径必须分开算，一侧零 ERROR 不能替另一侧背书；
- **验收**：Demo_AS/Script 27 个 `.as` + AS-Cache 414 个 `.d.as` 全部零 ERROR，corpus 40 条全通过；
  **注意盲区**：语料零 ERROR 不覆盖 4 个「导出器已实现但当前语料零出现」的 tag 形态（§8 风险 8）。
  其中 `@templateSpecialization class TArray<FVector>` 已于 2026-09 **单独实测零 ERROR**
  （连同 `struct TMap<K,V>`、`class TSubclassOf<T>`），文法无需改动；
- 与 BNF 的有意偏差（节点命名合并、`(void)` 形参、模板声明头 `struct TMap<K,V>`、`enum` 尾随 `;` 可选等）集中记录在 `grammar/README.md#与-bnf-的偏差`。

### 4.3 类型系统

```rust
enum TypeRef {
    Concrete(TypeId),                      // FVector
    Param(u32),                            // 模板参数 T（仅 .d.as 定义体内）
    Named(Name, Vec<TypeRef>),             // TArray<FVector>
    Const(Box<TypeRef>), Ref(Box<TypeRef>, RefKind),  // const / &in &out &
    Array(Box<TypeRef>),                   // T[]
}
```

- 模板实例化：惰性 + `(DefId, Vec<TypeId>)` 缓存 + 递归占位保护（`TArray<TArray<int>>`）；
- `@outputTypeIndex` 方法：不在实例化时展开，重载解析选定候选后从实参回填返回类型；
- 隐式转换表（`opImplConv`、`TSubclassOf→UClass` 等）：第一期只做补全/排序所需的子集，完整表留给诊断阶段。

### 4.4 声明展开规则表（取代引擎预处理器）

引擎预处理器的语义全部是静态规则，核心层直接展开，**不存在"生成代码"概念**：

| 源码形态 | 展开规则 |
|---|---|
| `delegate R N(A);` | struct N + `Execute/ExecuteIfBound/BindUFunction/opAssign/默认与拷贝构造/绑定构造` |
| `event R N(A);` | 同上但多播：`Broadcast/AddUFunction`（无 Execute） |
| `f"{expr}"` | 类型 = `Format` 重载的返回类型（FString）；插值段递归进表达式索引（references 必须覆盖） |
| `n"Name"` | 字面量类型 FName |
| `asset X of T` | 全局符号 X : 资产句柄类型 |
| 类 C 隐含成员 | `C.StaticClass()` / 命名空间同名访问 |

delegate 展开的成员集来自引擎 `ProcessDelegates` 的生成模板（已逐行核对，见讨论记录），约 15 行 Rust 即可表达。

### 4.5 符号查找链（语义正确性的核心，逐条对齐旧 LSP）

```
0. this / super（语境限定：类方法体内）
1. 局部变量（作用域链上溯）
2. 当前类成员（class 沿 supertype 链；struct 单层，见下）
3. 属性访问器模拟（Get<X>/Set<X>，读写侧分别命中）
4. mixin 函数（**fallback**：2/3 级全空 + 有对象上下文 + 无 scope 限定时才查）
5. 命名空间链（逐级回退父命名空间）
6. 全局符号 / 类型本身（静态调用）
约束：mixin 五条准入条件（见下）、local 函数的模块隔离
```

**逐级的实现约定**（补充说明，落地形态见 [`LSP实现规划.md`](LSP实现规划.md) §7.1）：

| 级 | 约定 |
|---|---|
| 0 | `this` 在 class/struct 方法体内 = 所在类型；静态与命名空间函数中不存在。`super` 仅 class 内有效（struct 无父类），解析为直接父类，用于 `Super::Foo()` 显式调用父实现 |
| 2 | **class 沿继承闭包上溯；struct 只查单层**——`.d.as` 的 struct 无父类（§2.4.2），且 C++ USTRUCT 继承在绑定层已展平成自有成员（[struct 专题](../as-docs/struct类型专题.md) §6.3）。为 struct 建继承闭包是无效工作，且会掩盖「展平」这一事实 |
| 3 | **默认所有方法都是访问器候选，带 `@notProperty` 的除外**（反向默认，§2.4.5）。自动生成的 `Get*/Set*` 已在导出期转成属性声明，不在此级处理 |
| 4 | mixin 函数是**普通全局函数**（不是任何类的成员），靠首参类型倒排充当扩展方法。**五条准入条件严格对齐引擎**，详见 §4.5.1 |
| 6 | 类型名与同名 namespace 可能是两个不同 DefId（§2.2.1 推论 1），按语境择一：`FVector v` → 类型；`FVector::ZeroVector` → 命名空间 |

**`local` 函数**（BNF §2.6）仅在声明所在模块可见 → `DefData` 需记 `local` flag + 模块归属，
跨模块查找时过滤掉。

#### 4.5.1 mixin 函数的准入条件（引擎取证）

真值 = `[ENGINE]as_compiler.cpp:13387-13450`（`// Look for mixin functions` 段）。
该 if 的守卫条件逐项对应如下，**五条必须全部满足**：

| # | 引擎条件 | LSP 侧含义 |
|---|---|---|
| 1 | `funcs.GetLength() == 0` | **纯 fallback**：第 2/3 级（类成员、属性访问器）**只要命中一个就绝不查 mixin**。mixin 不参与与真实成员的重载排序 |
| 2 | `objectType != 0 \|\| ThisObjectType != nullptr` | 必须有对象上下文：显式 `Obj.Heal(5)`，或**类方法体内**隐式 `Heal(5)`（引擎自动压入 `this`，`:13436-13449`）。全局函数体内无 `this` ⇒ 不查 |
| 3 | `scope.GetLength() == 0` | **带命名空间限定不走 mixin**：`NS::Heal(Obj)` 不解析为 mixin 调用 |
| 4 | `while (ns) { ...; ns = GetParentNameSpace(ns); }` | mixin 查找**自身也要逐级回退父命名空间**，不是只看当前 ns |
| 5 | 首参过滤（`:13417-13419`） | 首参存在 && `IsObject()` && `availableObjectType->DerivesOrShadows(首参类型)`。注意是 **`DerivesOrShadows`** 而非单纯继承——含 shadow 语义（AS 脚本类 shadow C++ 类），比「当前类或其基类」更宽 |

**两种声明形式都要识别**（索引期等价）：

```angelscript
mixin void Heal(AActor Target, float Amount) { ... }    // 前置：ParseMixin（as_parser.cpp:3700）
void Heal(AActor Target, float Amount) mixin { ... }    // 后置属性：ParseMethodAttributes（:3249 / :5083）
```

两者都在 `GetParsedFunctionDetails`（`as_builder.cpp:4604`）打上 `asTRAIT_MIXIN`。

其它约定：

- **命中后 definition / hover 落回 mixin 函数声明本身**（它是真实全局函数，不是合成符号）；
- **首参可以是 struct**：过滤条件只要求 `IsObject()`，而 AS 的 value type 亦满足 ⇒
  脚本可为 struct 写 mixin（`FVector` 等）；
- `asTRAIT_MIXIN` 在引擎编译器里**只有一处额外用途**：no-discard 判定时按 const 方法对待
  （`as_compiler.cpp:18627`）——返回值未使用会警告。符号查找本身不因该 trait 特殊化；
- **mixin class 不存在**：`ParseMixin` 只接函数声明，原版的 mixin class 机器
  （`RegisterMixinClass` / `IncludeMethodsFromMixins` / `mixinClasses`）是上游遗留的
  **不可达死代码**。文法层不实现，与引擎一致
  （[对比文档 §5.2](../as-docs/原版AngelScript与UE-fork对比.md#52-清单已逐项取证)）。

#### 4.5.2 C++ 侧 `ScriptMixin` —— 同名但无关，LSP 无需处理

UE fork 的主力 mixin 用法在 C++ 侧，与上述脚本 mixin **机制完全无关**：

```cpp
UCLASS(Meta = (ScriptMixin = "FVector"))          // [UE]Public/FunctionLibraries/AngelscriptMathLibrary.h:322
class UAngelscriptFVectorMixinLibrary : public UObject
```

绑定期 `Helper_FunctionSignature.h:283-345` 把这些**静态 UFUNCTION** 直接转成目标类型的
**真成员方法**（`EBindTargetType::MixinMethod`，并摘掉首参）。引擎自带一大批：
`FVector`/`FRotator`/`FQuat`/`FTransform` 数学库、`GameplayTag*MixinLibrary`、
`InputComponentScriptMixinLibrary`、`UWidget`/`UWorld`/`UAssetManager` 库等。

⇒ **对 LSP 完全透明**：它们在 `.d.as` 里导出时已是普通成员方法形态（首参已摘除），
走第 2 级成员查找即可，**不进 mixin 倒排**。`FVector.Dot()` 很可能来自 mixin 库，
但 LSP 只当它是成员方法——来源不可见，也不需要可见。

另：脚本 mixin 在 UE 反射层的效果仅限编辑器——给生成的 UFunction 打 `MixinArgument` +
`DefaultToSelf` meta（`AngelscriptClassGenerator.cpp:3324-3331`，`#if WITH_EDITOR`），
用于蓝图节点首参默认连 self。与 AS 侧调用语义无关，LSP 不消费。
