# my-angel-script-lsp 架构设计

> 版本：v0.1（初始设计）
> 前置文档：`../grammar/angelscript.bnf`（Unreal Angelscript 完整语法规范，tree-sitter 实现的依据）
> 参考实现：`C:\MyGit\ai-mylua-lsp`（tree-sitter + Rust + TS 三层架构的既有经验）
> 行为基准：Hazelight `vscode-unreal-angelscript`（现有 LSP 的语义行为作为验收对照）

## 0. 背景与目标

### 0.1 现状问题

Hazelight 的 `vscode-unreal-angelscript` LSP 存在结构性缺陷：

- **类型真值来源是运行时引擎**（TCP 27099 的 DebugDatabase），引擎不启动时 hover/定义/引用全部失效；
- 解析器是 Peggy/PEG + 手写语句切片，容错设计服务于"逐语句增量"，难以现代化；
- LSP（Node.js）单线程，大项目解析队列会阻塞事件循环。

### 0.2 目标

**类型真值来源 = `.as` 源码 + `.d.as` 导出声明文件**，引擎连接降级为可选增强：

| 功能 | 数据来源 | 是否需要引擎在线 |
|---|---|---|
| hover / 定义跳转 / 引用 / 补全 / 重命名 | `.as` + `.d.as` | 否 |
| semantic tokens / 文档符号 / 折叠 | tree-sitter CST | 否 |
| 诊断（第一阶段） | 引擎 Diagnostics 消息 | 是（后续逐步本地化） |
| 调试（DAP）/ 资产名补全 / 跳 C++ 源码 | 引擎 | 是 |

### 0.3 与 mylua-lsp 的复杂度对比

AS 是强类型语言，`.d.as` 是机器生成的规范声明——相比 mylua-lsp 需要处理的弱类型 + EmmyLua 注释随意性，**类型索引层大幅简化**：

- 无需猜类型（emmytype 的 `@param` 可能缺失/冲突/过时）；
- 声明是穷尽的（引擎反射全量导出），无需启发式回退；
- 泛型是编译期单态化（无协变推导、无特化匹配），实例化是纯查表+克隆。

## 1. 总体架构

```
+-----------------------------------------------------------------------+
|                    模块一：UE 导出插件（C++，Editor DLL）               |
|   菜单命令 → 遍历 AS 引擎注册类型 → 生成 .d.as → <Project>/Saved/AS-Cache |
+------------------------------------+----------------------------------+
                                     |  .d.as 声明文件（按 UE 模块分文件）
                                     v
+-----------------------------------------------------------------------+
|              模块三：LSP 核心层（Rust，独立 crate）                     |
|  tree-sitter 解析(.as/.d.as) → 符号索引 → 类型推导 → LSP 响应           |
+------------------------------------^----------------------------------+
                                     |  JSON-RPC (stdio)
                                     v
+-----------------------------------------------------------------------+
|              模块四：VSCode 扩展（TypeScript）                          |
|  客户端启动/配置/命令 + （远期）DAP 透传                                 |
+-----------------------------------------------------------------------+

模块二（tree-sitter grammar）被模块三内嵌使用，不是独立进程。
```

技术栈对齐 mylua-lsp：tree-sitter（语法）+ Rust（核心，含 LSP 服务）+ TypeScript（扩展宿主）。

## 2. 模块一：UE 导出插件

### 2.1 形态与入口

- **项目 Editor 插件**（如 `Demo_AS/Plugins/AngelscriptTypeExporter`，或放 `Source/` 下随项目编译），依赖 `AngelscriptCode` 模块；
- 入口：编辑器菜单 `Tools > Angelscript > Export Type Declarations (.d.as)`，同步命令（导出耗时秒级，带 SlowTask 进度）。

### 2.2 数据源与过滤

数据源与 `FAngelscriptDebugServer::SendDebugDatabase` 相同：遍历 `FAngelscriptManager::Get().Engine` 的全部注册类型 + 全局函数/枚举/属性，**但过滤掉脚本类型**：

```cpp
// 伪代码
for (each ObjectType)
    if (Type->GetFlags() & asOBJ_SCRIPT_OBJECT) continue;   // 脚本类由 LSP 解析 .as 获得
    if (TypeName.IsEmpty() || TypeName[0] == '_') continue;  // 内部类型
    ExportType(Type);
```

脚本类型（`asOBJ_SCRIPT_OBJECT`）**不导出**——它们能从 `.as` 源码完全推导，导出只会造成双源冲突。

**待调研（分组依据）**：用户要求"按 module 一个文件"。可选方案：
- (a) 枚举 `FAngelscriptBinds` 注册表，按声明所在 Bind 文件/所属 UE 模块分组（最准确，需确认注册表可枚举性）；
- (b) 按 AS 类型的 namespace / UClass 的 UPackage 分组；
- (c) fallback：内置分组表（UObject 系 / 数学与容器 struct / 枚举 / 各函数库 namespace），少量大文件。

v1 允许先落 (c) 验证格式，(a) 作为 v2 优化。

### 2.3 输出位置

```
d:\WorkGit\UEProjs\Demo_AS\Saved\AS-Cache\
    _manifest.dctx          # 清单（版本指纹、文件列表、设置）
    Engine.d.as             # 期望的按模块分组示例
    Gameplay.d.as
    ...
```

**注意**：`Saved/` 会被"清理项目"清空且不入 git——这是刻意的（导出物是缓存不是源码）。提供菜单第二项 `Copy Declarations to Project`（复制到 `Script/../TypeDecls/` 等版本库路径）供需要 git 版本化的项目使用；LSP 侧通过配置项声明搜索路径。

### 2.4 `.d.as` 文件格式

**核心决策：`.d.as` 使用 AngelScript 自身语法**（无函数体的声明），不发明独立 DSL。语法上就是 BNF 中 `function_decl ::= ... ( ';' | statement_block )` 取 `';'` 分支、类成员取声明子集。

```angelscript
// ==== AngelscriptTypeDeclarations v1 ====
// @engine 5.5.x-branch (commit hash)
// @plugin Angelscript (commit hash)
// @floatIsFloat64 true
// @exported 2026-09-26T14:00:00

struct FVector
{
    float X;
    float Y;
    float Z;

    // Dot product of two vectors.
    float Dot(const FVector& Other) const;
    FVector operator+(const FVector& Other) const;
}

class AActor : UObject
{
    // @event @keywords actor;transform
    // @unrealname K2_GetActorLocation
    FVector GetActorLocation() const;

    void SetActorLocation(const FVector& NewLocation);
}

class TArray<T>        // 模板：类型参数显式声明
{
    // @template_covariant
    int Num() const;
    T Get(int Index) const;
    bool IsEmpty() const;
}

namespace Math
{
    float Sqrt(float Value);
}
```

**注解标签（注释行 `// @tag value`，声明前）**——BNF/JSON 字段到 `.d.as` 的完整映射：

| 引擎字段 | `.d.as` 承载 |
|---|---|
| `inherits` / `isStruct` / `isEnum` | `class X : Y` / `struct` / `enum` 语法 |
| `properties`（类型/protected/flags） | 属性声明 + `protected` |
| `methods`（签名/const/默认值/`&in/&out`） | 函数签名语法 |
| `doc` | 声明前普通注释（现有 comment_documentation 机制） |
| `subtypes` / 模板标志 | `class T<X, Y>` + `@template_covariant` 等 tag |
| `event` / `ufunction` | `@event` / `@ufunction` |
| `unrealname` / `keywords` / `meta` | `@unrealname` / `@keywords` / `@meta` |
| `outputTypeIndex` | `@outputTypeIndex N`（返回类型由第 N 实参决定） |
| `defaultsonly` / `callable:false` | `@defaultsOnly` / `@notCallable` |
| `floatIsFloat64` 等设置 | 文件头 `@floatIsFloat64` |

### 2.5 失效策略

`_manifest.d.ctx` 记录引擎版本/插件版本指纹。LSP 启动时校验，不匹配 → 降级为"仅 .as 源码"模式并提示重新导出（绝不静默用过期声明）。

## 3. 模块二：tree-sitter 语法解析（**已完成**，见 `grammar/README.md`）

- `grammar/grammar.js` 按 `grammar/angelscript.bnf` 实现（该 BNF 已含 tree-sitter 实现注记：优先级表 §5.5、节点命名表 §5.6、冲突清单 §5.4）；BNF 文件已随文法一起移入 `grammar/`；
- **外部 scanner（scanner.c）只保留 format string**：`format_string_content`（逐字保留文本/空格/`{{`转义）+ `format_spec`；heredoc `"""..."""`、`n"..."`、preproc 行用普通 token 即可；`>>` 无需拆分（模板实参位置不接受移位运算，词法状态自然切分）；
- **实际声明的冲突**（grammar.js `conflicts:`，对应 BNF §5.4）只有 4 组：`type`/`_expression`、`parameter_list`/`argument_list`、`template_type`/`_expression`、`named_argument`/`_expression`(`/type`)；classic-for vs range-for、函数声明 vs 变量声明由这几组加动态优先级导出；
- 命名实参同时支持 `:` 与 `=`（引擎设置 `asEP_ALTER_SYNTAX_NAMED_ARGS = 1`）；
- 错误恢复：BNF §3.7 的 [lsp] 容错产生式**不做成具名规则**，交给 tree-sitter 内建恢复 + 查询侧容错，关键中途编辑形态在 `test/corpus/error_recovery.txt` 固定快照；
- `.d.as` 与 `.as` 同一语法（`.d.as` 是子集），**同一 parser**，按文件后缀/目录区分模块性质；
- **验收**：Demo_AS/Script 27 个 `.as` + AS-Cache 414 个 `.d.as` 全部零 ERROR，corpus 31 条全通过；
- 与 BNF 的有意偏差（节点命名合并、`(void)` 形参、模板声明头 `struct TMap<K,V>`、`enum` 尾随 `;` 可选等）集中记录在 `grammar/README.md#与-bnf-的偏差`。

## 4. 模块三：LSP 核心层（Rust）

### 4.1 crate 结构

```
crates/
  as-syntax/      # grammar.js/scanner.c + node 类型绑定（生成）
  as-core/        # 索引、类型系统、查找链（纯库，无 IO 依赖，可单测）
  as-lsp/         # tower-lsp（或手写）服务壳：请求路由、增量同步、$/progress
  as-cli/         # CLI 入口（dump-tree / dump-index，调试用）
```

### 4.2 workspace 与索引（三阶段，取代旧 LSP 的不动点迭代）

1. **声明快扫**：全工作区 `.as`/`.d.as` 一遍轻量扫描，收集全部顶层声明（类名/函数名/模块名→文件/范围）。等价旧实现的 `PreParsedIdentifiersInModules` 预扫描，但从辅助机制升级为**主索引**——彻底消除"依赖模块未解析完"的时序问题；
2. **全量解析**：rayon 并行 tree-sitter 解析，建符号表、作用域树、成员表；
3. **惰性语义**：类型推导/模板实例化在请求到达时按需计算并缓存（编辑按文件粒度失效）。

模块命名沿用引擎规则（`FilenameToModuleName`：去 `.as`、`/`→`.`），保证与引擎诊断/模块隔离语义一致。多根 workspace：每根独立索引，全局符号表合并（同名冲突按"项目根优先于引擎根"消解）。

### 4.3 类型系统

```rust
enum TypeRef {
    Concrete(TypeId),                      // FVector
    Param(u32),                            // 模板参数 T（仅 .d.as 定义体内）
    Named(Name, Vec<TypeRef>),             // TArray<FVector>
    Const(Box<TypeRef>), Ref(Box<TypeRef>, RefKind),  // const / &in &out &
    Array(Box<TypeRef>),                   // T[]
}
```

- 模板实例化：惰性 + `(DefId, Vec<TypeId>)` 缓存 + 递归占位保护（`TArray<TArray<int>>`）；
- `@outputTypeIndex` 方法：不在实例化时展开，重载解析选定候选后从实参回填返回类型；
- 隐式转换表（`opImplConv`、`TSubclassOf→UClass` 等）：第一期只做补全/排序所需的子集，完整表留给诊断阶段。

### 4.4 声明展开规则表（取代引擎预处理器）

引擎预处理器的语义全部是静态规则，核心层直接展开，**不存在"生成代码"概念**：

| 源码形态 | 展开规则 |
|---|---|
| `delegate R N(A);` | struct N + `Execute/ExecuteIfBound/BindUFunction/opAssign/默认与拷贝构造/绑定构造` |
| `event R N(A);` | 同上但多播：`Broadcast/AddUFunction`（无 Execute） |
| `f"{expr}"` | 类型 = `Format` 重载的返回类型（FString）；插值段递归进表达式索引（references 必须覆盖） |
| `n"Name"` | 字面量类型 FName |
| `asset X of T` | 全局符号 X : 资产句柄类型 |
| 类 C 隐含成员 | `C.StaticClass()` / 命名空间同名访问 |

delegate 展开的成员集来自引擎 `ProcessDelegates` 的生成模板（已逐行核对，见讨论记录），约 15 行 Rust 即可表达。

### 4.5 符号查找链（语义正确性的核心，逐条对齐旧 LSP）

```
1. 局部变量（作用域链上溯）
2. 当前类成员（沿 supertype 链）
3. 属性访问器模拟（Get<X>/Set<X>，读写侧分别命中）
4. 命名空间链（逐级回退父命名空间）
5. 全局符号 / 类型本身（静态调用）
约束：mixin 可见性（仅 args[0] 为本类基类时类内可见）、模块隔离规则
```

### 4.6 LSP 功能映射（第一阶段范围）

| 功能 | 实现要点 |
|---|---|
| hover | 查找链命中 → 签名渲染（对齐旧 LSP 的 markdown 片段格式）+ doc 注释 |
| definition/implementation | 符号声明位置；`.d.as` 声明是合法落点 |
| references/rename | 全工作区符号引用索引；重载按实参类型消歧（消歧失败报全部重载）；f-string 插值段纳入扫描；`$/progress` 长任务通知 |
| completion | 关键字 + 查找链上下文补全 + 成员补全（`X.` / `X::` 后）+ UFUNCTION/UPROPERTY 说明符（schema 驱动）+ 命名参数 |
| signatureHelp | 重载集 + 实参类型排序 |
| documentSymbol/workspaceSymbol | CST 直接映射 |
| semanticTokens | CST 映射，legend 沿用旧扩展（`as_typename` 等约 20 类） |

UTF-16 列号：沿用 mylua-lsp 的成熟方案。

### 4.7 与引擎在线通道的关系（第一阶段实现为"仅读"）

第一期不做引擎连接。第二期按需加：诊断透传（引擎 Diagnostics 消息）、资产库。**架构上保证**：没有这条通道时上述所有第一阶段功能不受影响。

- 语言 id：**`angelscript-asl`（暂定，避开与 Hazelight 扩展的 languageId 冲突）**——或提供 `angelscript` 接管开关，二者共存由用户选择；
