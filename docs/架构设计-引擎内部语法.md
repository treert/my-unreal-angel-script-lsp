## 1. 通配类型 `?`

### 1.1 是什么

- `?` 是**只能在 C++ 注册串里出现**的"任意类型"形参标记，脚本作者永远不能在 `.as` 里声明它；
- 原版 SDK 要求写成 `?&in` / `?&out`，UE fork 放宽为也接受裸 `?&`（如 `Bind_UObject.cpp` 的
  `void opCast(?& Address) const`）；
- 它不是脚本语法，但 `.d.as` 导出声明里会大量出现，所以 tree-sitter 文法必须认识它。

### 1.2 `.d.as` 中的形态（已确认接受）

导出器（`TypeDeclarationExporter.cpp` 的 `ttQuestion` 分支）与 DebugServer（`AngelscriptDebugServer.cpp`
发送 `"type": "?"`）行为一致：**统一输出裸 `? ParamName`，丢弃 `&` 及方向信息（`&in`/`&out`）**。

决策：接受该失真，不做保真改造。理由：

- 脚本侧本来就不能写 `?` 类型，LSP 无消费 `?&out` 方向信息的场景；
- 保持与 DebugServer / 旧 LSP 输出的逐字节一致，方便行为对照。

全量语料约 20+ 处，典型：`FString.opAdd/opAddAssign/Append/Format`、`FText.Format`、
`DataTable.GetRow/AddRow/GetAllRows`、`GetAllActorsOfClass`、`FJsonObjectConverter.*`、
`FInstancedStruct.Make`。

### 1.3 文法层（已完成，勿重复处理）

- `grammar/grammar.js`：`wildcard_type` 规则（独立节点，不复用 `auto_type`）；
- `grammar/test/corpus/declarations.txt`：`void WildcardParameter(? Address) const;` 快照；
- 414 个 `.d.as` 零 ERROR 验收即包含此项。

### 1.4 语义层约定（as-core，P3 实现时执行）

| 环节 | 约定 |
|---|---|
| TypeRef | 增加 `Wildcard` 变体。**与 `auto` 严格区分**：`auto` 是用户可写的声明侧推导占位，`?` 是形参位的"匹配任意"，不得复用同一表示 |
| 重载解析 / 实参检查 | `?` 形参匹配任意实参类型，候选**排序最低**（避免遮蔽具体重载，如 `FString.opAdd(?)` vs `opAdd(FString)`） |
| hover / signatureHelp | 原样渲染 `?`，无特殊处理 |
| 默认值 | 引擎侧 `?` 参数均无默认值，无需处理 |
| 诊断（P5） | `?` 仅允许出现在 `.d.as` 形参位；用户 `.as` 中出现即报错（诊断码挂 `AS0001+` 系列，见[对比文档](原版AngelScript与UE-fork对比.md)） |

### 1.5 `opCast(?&)` 补充说明

`UObject.opCast(?& Address) const` 是编译器级的 universal cast 钩子，由 `cast<T>(Obj)`
显式转换触发，脚本不会直接调用它。

决策：**导出端不过滤、LSP 侧不硬性隐藏**（语法合法、与 DebugServer 输出一致）。
后续若成员补全里这个签名造成困扰，在补全排序中对"名为 `opCast`/`opImplCast` 且含 `?` 形参
的方法"降权即可，不改数据源。

## 2. `auto`（对照条目）

用户可写的推导占位，仅允许出现在局部变量与 range-for 迭代器声明位（BNF 注记）。
与 `?` 的区别见 §1.4——两者都在 `DATATYPE` 产生式里，但语义角色不同，节点与 TypeRef 表示均分开。
