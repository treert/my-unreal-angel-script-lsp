## 0. 为什么所有诊断都必须带 code

1. **golden 对账**：P5 的验收方式是「引擎 Output 的报错」与「LSP 诊断」逐条比对，
   靠 code 而不是靠消息文本匹配，才能容忍措辞微调。
2. **用户抑制**：规划中的 `// as-ignore: AS0102` 行内抑制需要稳定标识。
3. **共存**：与 Hazelight 扩展同时启用时诊断会双报（[架构设计 §8](架构设计.md#8-风险与未决问题) 风险 4），
   带 code 才能按条抑制而非整体关闭。
4. **文档索引**：差异文档与专题文档用 `→ AS0201` 这种标记引用具体约束，避免重复描述触发条件。

## 1. 编码规则

```
AS <大类1位> <序号3位>        例：AS0102
```

| 大类 | 区段 | 含义 | 主要来源 |
|---|---|---|---|
| 0 | `AS0001-0099` | **语法/解析**：parser 直接拒绝的形态 | `[ENGINE]as_parser.cpp` |
| 1 | `AS0100-0199` | **类型系统**：值/引用二分、句柄、转换、布局 | `as_builder.cpp` / `as_compiler.cpp` / Binds |
| 2 | `AS0200-0299` | **UE 反射**：`UCLASS/USTRUCT/UFUNCTION/UPROPERTY` specifier 约束 | `[UE]AngelscriptPreprocessor.cpp` |
| 3 | `AS0300-0399` | **GC / 属性生成** | `[UE]AngelscriptClassGenerator.cpp` |
| 4 | `AS0400-0499` | **符号解析**：未定义名、重载、命名冲突 | 本 LSP 自有（引擎侧散落多处） |
| 9 | `AS0900-0999` | **本 LSP 独有**（引擎无对应，如 `.d.as` 过期、文法未支持形态） | — |

约定：

- **消息文本尽量逐字沿用引擎原文**（各表 `Message` 列），只把 `%s` 换成实际符号名。
  这样用户在引擎 Output 里搜到的错误和 LSP 报的能对上，也便于 P5 的逐条对账。
  措辞偏离引擎的必须在该表下方显式注明（目前仅 `AS0106`）。
- `Sev` = 默认严重级：`E` = Error，`W` = Warning。
- 新增码**只能追加**，不得复用已废弃的号。废弃时在表中保留并标 `~~AS0xxx~~ (retired)`。
- `AS0000` 保留不用（避免与"无 code"混淆）。

## 2. AS00xx — 语法 / 解析

| Code | Sev | Message（引擎原文） | 触发条件 | 引擎位置 |
|---|---|---|---|---|
| `AS0001` | E | `Expected method or property` | `struct` 内出现 `default` 语句 | `as_parser.cpp:3835`（`TXT_EXPECTED_METHOD_OR_PROPERTY`） |
| `AS0002` | E | `Unexpected variable declaration` | 非块内声明，如 `if (x) int y = 5;` / case 子句内 | `as_parser.cpp` `ParseStatement`（`TXT_UNEXPECTED_VAR_DECL`） |
| `AS0003` | E | `Unexpected token 'fallthrough'` | `fallthrough` 出现在 case 子句末尾以外 | `ParseStatement` 无 `ttFallthrough` 分支 |
| `AS0004` | E | `Reference is not allowed here` | 全局变量 / 类成员上写 `&` | `as_parser.cpp` `ParseDeclaration`（`!isClassProp && !isGlobalVar` 守卫） |
| `AS0005` | E | `Property accessor must be implemented` | 无实现的虚属性访问器 `get;` / `set;`（该形态本是给死 token `interface` 用的，**实际必错**） | `asCBuilder::RegisterVirtualProperty` |

> **本段存在的理由**：文法刻意比引擎宽松（见 [`../grammar/README.md`](../grammar/README.md)
> 「语法接受 ≠ 语义合法」），上述形态都能正常建树，由诊断层报错而非解析错误——
> 这样中途编辑时整棵树不会崩掉。

> **`AS0106` 措辞偏离引擎**：引擎只是**静默不给 struct 注册** `opCast`，报错最终落到通用的

> 此类偏离必须在本表下方登记——目前只有这一条。

背景见 [`struct类型专题.md`](../as-docs/struct类型专题.md)：§4（语义对照）、§6（继承四道锁）。

## 8. range 与 quick fix 约定

引擎侧的报错大多只给 **chunk 行号**（预处理器）或单 token 位置（parser）。
本 LSP 有完整 CST，**应当做到精确到 token**，这是相对官方 Hazelight LSP 的可见优势。

| Code | range 应落在 | quick fix |
|---|---|---|
| `AS0001` | `default` 关键字到语句末 | 删除该语句 |
| `AS0002` | 整个变量声明 | 提升到外层块 |
| `AS0003` | `fallthrough` 关键字 | 改为 `break` |
| `AS0004` | `&` 符号 | 删除 `&` |
| `AS0102` / `AS0201` | **父类名节点**（不是整个声明） | 删除继承列表 |
| `AS0202` | `UFUNCTION()` 宏节点 | 删除宏 |
| `AS0103` / `AS0106` | 类型引用节点 | — |
| `AS0104` | 构造调用表达式 | 提示改用 `NewObject` / `SpawnActor` |
| `AS0204` | 出错的那个 specifier token | — |
| `AS0301` | 成员声明的类型节点 | 添加 `UPROPERTY()` |
| `AS0901` | 文件级（`0:0`） | 触发 `Export Type Declarations` 命令 |

## 9. 实施约束

1. **`AS00xx`-`AS04xx` 段是「复刻引擎行为」**，每加一条都必须有引擎侧证据（`文件:行号`）。
   没有证据的检查一律放 `AS09xx`。P5 之前不得自行发明这些段的码号。
2. **先占号，再写代码**。本文是唯一分配处；实现里禁止出现未登记的 code 字符串。
3. **对账测试**：每个 `AS0001`-`AS0399` 码至少一条最小复现 `.as` 用例，
   断言「本 LSP 的 code + range」与「引擎 Output 的报错行」一致。
4. **实现侧建议**：Rust 端用单一 `enum DiagCode` 承载全部码号，
   `Display` 输出 `AS0102` 形式，避免散落字符串字面量；本文与该 enum 一一对应。
