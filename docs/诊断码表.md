## 1. 命名与登记规则

- 名字形态：**kebab-case 小写，取自触发条件**（自解释——抑制注释与 Problems
  面板里无需翻表。官方扩展与引擎均无码号体系，无外部对齐约束）；
- **实现时才登记**：素材表（§3）只是「引擎在这些情况下会报错」的取证，
  P5 挑选实现时才命名进 §2——**不预登记、不预命名**（诊断逐渐完善，
  不做提早设计）；
- 名字是稳定标识（`Diagnostic.code` / `as-ignore` / 未来配置项共用同一名字），
  **登记后不改名**——语义变化宁可新增新名再废弃旧名（废弃条目标 retired 保留）；
- Rust 端用单一 `enum DiagCode` 承载，`Display` 输出名字原文（kebab-case）。

**为什么诊断要带名字**（三条都与实现进度无关，故现在就定）：

1. **用户抑制**：`// as-ignore: cyclic-inheritance` 式行内抑制需要稳定标识；
2. **与 Hazelight 扩展共存**：同时启用会双报（[架构设计 §8](架构设计.md#8-风险与未决问题) 风险 4），
   带名字才能按条抑制而非整体关闭；
3. **自解释**：`missing-type-decls` 一眼看懂，`AS0902` 必须翻表——数字码
   不携带语义，这是 v1.x 数字码被弃用的原因（D42）。

## 2. 已实现诊断（登记处）

| 名字 | 状态 | severity | range 落点 | 实现要点 |
|---|---|---|---|---|
| `missing-type-decls` | ✅ M6 | Warning | 文档 (0,0) 零宽 | 触发条件合并为「索引内 `.d.as` 数为 0」（dirs 全空与目录无文件两形态统一）；仅对 Script 文档发布（Phase D 起扩到全部 Script 文件）；每次重建后重判 |
| `parse-error` | ✅ M6 | Error | `ERROR`/`MISSING` 节点区间 | **语义泛化**（D36）：一切 tree-sitter 解析错误即报——逐节点一条、不深入 ERROR 子树重复计数（`as_syntax::verify_tree` 既有契约）；f-string 嵌套格式说明符是最典型案例 |
| `cyclic-inheritance` | ✅ Phase D | Error | 环成员类的 base 名字区间（`bases[0].span`） | 工作区级事实（每轮 drain 经 `cycle_diags()` 现算一次）；Decl 文件成员跳过（导出器不产环，腐坏导出不在诊断面）；结构变化 / 快照发布触发全量重诊断时按文件分发 |
| `undefined-function` | ✅ P5 首条 | Error | 裸 callee 名字区间 | 调用点走完整查找链（局部 → 成员/访问器/mixin → 命名空间 → 全局，`resolve_callee` 同链——与 hover / goto-definition 同一解析真值）无命中即报；只查裸标识符 callee（成员调用 `A.B()` 依赖接收者定型不查、模板构造独立成 `template_type`）；不深入 ERROR 子树；decl 全缺失（`missing-type-decls` 触发）时整类跳过（引擎函数一概不可解析，纯噪音）；仅对 Script 文件发布。已知失真：引擎函数存在但未导出（数据源缺口，future-work 4.x）时误报，重新导出 `.d.as` 自愈，可 `as-ignore` 抑制 |

### 2.1 行级抑制

```angelscript
// as-ignore: parse-error                          ← 同行：抑制该行起始的指定名诊断
// as-ignore: missing-type-decls, parse-error       ← 逗号分隔多名
// as-ignore-next-line: parse-error                 ← 上一行：抑制下一行
// as-ignore                                        ← 无名：抑制该行全部诊断
```

- 命中口径：诊断 range **起始行**落在生效行；`missing-type-decls` 落 (0,0)
  ⇒ 文件首行可抑制；
- 未知名（`DiagCode` 未收录，含素材表里的全部触发条件）静默忽略——与 D15
  「未登记 tag 静默忽略」同族；块注释不识别；字符串字面量里的标记会误认
  （已知失真，接受——失真面分析见 as-core `diag.rs` 模块头）；
- 官方扩展无既有惯例（已查 `ls_diagnostics.ts`，其无行内抑制机制）——本 LSP
  自定。诊断 `source` 一律 `my-as-lsp`。

> **`floatIsFloat64` 不设诊断**：配置项配错属静默错误（类型宽度偏差），无法自动检出
> （[架构设计 §8](架构设计.md#8-风险与未决问题) 风险 11）。缓解靠默认值对齐引擎 +
> 状态栏常显生效值。

## 3. 已取证的引擎约束（素材，非实现承诺）

以下形态**引擎确实会报错**，且已定位到源码。**文法刻意放行**它们
（[`../grammar/README.md`](../grammar/README.md)「语法接受 ≠ 语义合法」：中途编辑时整棵树不会崩），
因此若要报错就得靠语义层。P5 按需选用，**未必全部实现**；实现时从本表挑触发条件、
另行命名登记进 §2。

「引擎原文」列是取证结果，仅供参考对照——**不是措辞承诺**，本 LSP 可自行拟定更清晰的表述。

| 触发条件 | 引擎原文（参考） | 引擎位置 |
|---|---|---|
| `struct` 内出现 `default` 语句 | `Expected method or property` | `as_parser.cpp:3835` |
| 非块内声明，如 `if (x) int y = 5;` / case 子句内 | `Unexpected variable declaration` | `as_parser.cpp` `ParseStatement` |
| `fallthrough` 出现在 case 子句末尾以外 | `Unexpected token 'fallthrough'` | `ParseStatement` 无 `ttFallthrough` 分支 |
| 全局变量 / 类成员上写 `&` | `Reference is not allowed here` | `as_parser.cpp` `ParseDeclaration` |
| 无实现的虚属性访问器 `get;` / `set;`（**实际必错**：该形态本为死 token `interface` 而设） | `Property accessor must be implemented` | `asCBuilder::RegisterVirtualProperty` |
| `class` 的父类解析成 struct / 非 UObject 类型 | `Structs cannot be base classes for anything` | `as_texts.h:172`；`as_builder.cpp:2293-2296` |
| 继承 struct（`asOBJ_NOINHERIT`）或 final class | `Can't inherit from class '%s' marked as final` | `as_texts.h:61`；`as_builder.cpp:3200-3207` |
| 对 struct 取句柄 | `Object handle is not supported for this type` | `as_texts.h:222`；`as_compiler.cpp:13886` |
| 用构造语法创建 class（`asOBJ_DISALLOW_INSTANTIATION`） | `Cannot create this object type by constructor. For actors, use SpawnActor()...` | `as_compiler.cpp:12861` |
| struct 布局自递归 | `Type %s includes a struct that includes itself.` | `as_builder.cpp:3422` |
| 对 struct 用 `Cast<>` | **引擎无专门报错**：静默不注册 `opCast`，最终落到通用「no conversion」 | `[UE]Private/Binds/Bind_UObject.cpp:135-137` |
| `struct F : G` | `Error parsing script struct %s. Structs may not inherit from anything.` | `AngelscriptPreprocessor.cpp:1125` |
| struct 内 `UFUNCTION()` | `Error parsing script struct %s. Structs may not have any UFUNCTION()s.` | `AngelscriptPreprocessor.cpp:1260` |

| class 名与非 class 的 UObject 撞名 | `Class %s has a name conflict with non-class unreal object %s.` | `AngelscriptClassGenerator.cpp:239-241` |
| struct 内含可能持有 UObject 引用的成员，但无法生成隐藏 `FProperty` | `Property %s with type %s is in a context where a UPROPERTY must be generated for GC reasons...` | `AngelscriptClassGenerator.cpp:299-301` |
| 缺 `ComposedStruct` meta | `Composed struct property %s does not have ComposedStruct meta in its UPROPERTY().` | `AngelscriptClassGenerator.cpp:1365-1367` |

**符号解析类素材**（同样未登记，实现时再命名）：裸 enum 值访问
