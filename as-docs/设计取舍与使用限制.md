## 0. 定位：这是一门「引擎同构语言」

Hazelight fork 的设计目标不是「更好的 AngelScript」，而是
**「Blueprint 的文本兄弟」**：脚本里写的每个构造都必须能被 UE 编辑器、
序列化器、网络复制、Blueprint 互操作直接消费。

这个定位决定了评估标准：语言特性不是按「表达力」取舍，而是按
「能不能进 UE 反射宇宙」取舍。**通不过的都砍**，无论它在通用语言里多基础。

## 1. 两条第一性原则

所有具体限制都能从下面两条推出来。理解了这两条，80% 的「为什么不能用」
不需要查文档就能自己推出来。

### 原则一：每个脚本值必须回答「生命周期归谁管」

fork 摘除了 AS 自带的 GC 与引用计数（证据链见
[对比文档 §3](原版AngelScript与UE-fork对比.md#3-gcas-自带垃圾回收被摘除)）。
后果：**每个存活的值必须有明确的生命周期归属**——

| 值的种类 | 归属 |
|---|---|
| class 实例 | 就是 UObject 本身（同一块内存，`[UE]Private/AngelscriptManager.cpp:206` 把对象分配劫持成 `NewObject`），UE GC 全权管理 |
| struct / 基础类型 | 值语义，内嵌宿主内存，随宿主生灭；内部的 UObject 引用由强制生成的 `FProperty` 暴露给 UE GC |
| **闭包 / 匿名函数对象** | **没有答案** —— 匿名堆对象、非 UObject、无 FProperty、捕获的 UObject 引用对 UE GC 不可见 → 整条路被堵死（§2.3） |

### 原则二：每个脚本构造必须能被反射描述

类型 = UClass/USScriptStruct/UEnum，函数 = UFunction，属性 = FProperty，
回调 = 动态委托（`UObject + FName` 二元组）。**反射描述不了的构造在 UE 宇宙里不存在**。

这条原则的推论最有杀伤力：C++ API 里所有 `TFunction<>` 参数的函数
**天然无法绑定**给脚本——所以 `[UE]Private/Binds/` 一百多个绑定文件里没有
一处暴露 TFunction 参数，全部在绑定层预先改造成委托或 `opCmp` 形态。
**限制不是「语言缺一角」，而是整个 C++ API 表面都被过滤了一遍**（§2.6）。

## 2. 取舍清单（逐项：砍了什么 → 为什么 → 替代品）

### 2.1 自建对象模型 → 寄生 UE 反射

- **砍掉**：AS 原生 class 对象（独立的堆对象 + AS GC）、`asOBJ_GC`、引用计数。
- **原因**：原则一。脚本 class 直接生成 `UASClass : UClass`
  （`[UE]Public/ClassGenerator/ASClass.h:11`），实例即 UObject。
- **得到**：继承/多态/接口概念全部借用 UClass；编辑器、序列化、复制、GC、BP 互操作「免费」。
- **代价**：class 不能用构造语法创建（`asOBJ_DISALLOW_INSTANTIATION`，
  `AS0104`）——必须 `SpawnActor` / `NewObject` / 组件 `Create()`。

### 2.2 显式句柄体系 → 隐式句柄

- **砍掉**：`@` 句柄、`null`、`is`/`!is`、句柄运算（token 全部移除，
  [对比文档 §1.1](原版AngelScript与UE-fork对比.md#11-被移除的原版-token第-251-307-行全部--注释)）。
- **原因**：句柄是 AS GC 时代的引用管理语法；生命周期归 UE 后，引用就是
  `UObject*`，值写法 `AActor A = ...` 足够（`asOBJ_IMPLICIT_HANDLE`）。
- **替代**：`nullptr` 判空、`==`/`!=` 比较、`Cast<T>`（大写）转型。

### 2.3 lambda / funcdef → 反射委托（**对表达力伤害最大的一项**）

- **砍掉**：lambda、funcdef、函数句柄（funcdef 是死 token；lambda 编译期必败，
  唯一出口 `ImplicitConvLambdaToFunc` 断言目标是 funcdef，
  `[ENGINE]as_compiler.cpp:8339`）。
- **原因**：两原则同时违反——闭包没有生命周期归属（原则一），
  也无法用 `(UObject, FName)` 描述（原则二，无法序列化/复制/进 BP/进细节面板）。
- **替代品 1**：命名 `UFUNCTION` + `AddUFunction(this, n"...")` /
  `BindUFunction`（`[UE]Private/Binds/Bind_Delegates.cpp:621-627`）。
- **替代品 2**：`FAngelscriptDelegateWithPayload` ——「委托 + 单个装箱捕获值」，
  官方对闭包需求的定向回应：

```
// BindWithPayload(UObject, FName, const ?&in Payload)
// 回调提升为 UFUNCTION，捕获值拷贝进 FInstancedStruct，执行时 ProcessEvent 注入
Delegate.BindWithPayload(this, n"OnLoaded", MyPayloadStruct);
```

- **残留缺口（诚实评估）**：
  - 行为当值传：`Sort(comparator)` 式 API 没了。引擎的解法是降维——
    `TArray.Sort()` 只用元素的 `opCmp`（`[UE]Private/Binds/Bind_TArray.cpp:1472`），
    多键排序/临时谓词/`Find(predicate)` 不存在；
  - 小回调必须提升为 UFUNCTION，污染类命名空间；
  - 捕获只能单值、按值拷贝、不能引用。

### 2.4 interface → 反射 + 委托

- **砍掉**：`interface` 声明（死 token）。
- **原因**：UE 的接口是 `UInterface` + 反射实现，脚本侧由 UClass 继承体系天然覆盖；
  AS 自有的接口概念没有对应的反射描述。
- **替代**：继承 UInterface 的 C++/BP 接口类（通过绑定层暴露），或纯虚 UFUNCTION 约定。

### 2.5 原生容器 / 字典 → UE 反射容器家族

- **砍掉**：AS 原生 `array<>` / `dictionary`、`string`（作为独立类型）。
- **原因**：原则二。容器要能做 UPROPERTY（编辑器可见、可复制、GC 可扫），
  就必须是反射容器。
- **替代**：`TArray<T>` / `TMap<K,V>` / `TSet<T>` / `TOptional<T>` /
  `TSubclassOf<T>` / `TObjectPtr` / `TSoftObjectPtr` / 委托族——全部由
  `FAngelscriptBinds::ValueClass` 包装绑定（`[UE]Private/Binds/Bind_TArray.cpp:1338` 等）。
- **代价**：没有 `TQueue`/`TStack`/链表；要新的容器形态只能回 C++ 写 `Bind_T*.cpp`。
- **注意**：容器内的 UObject 引用同样被 UE GC 跟踪——这是全量 GC 被强制的原因之一
  （`[UE]Private/AngelscriptManager.cpp:260-265` 硬断言禁用增量 reachability）。

### 2.5.1 脚本侧**不能定义**模板（只能用 C++ 注册的）

容器全家桶是模板，但**模板的定义权完全不在脚本侧**。这不是"没人实现"，而是
parser 层面的硬隔离：AS 有**两条独立的解析入口**。

| | 脚本文件路径 | C++ 注册串路径 |
|---|---|---|
| 入口 | `ParseScript` → **`ParseClass`** | **`ParseTemplateDecl`** |
| 位置 | `[ENGINE]as_parser.cpp:3734` | `[ENGINE]as_parser.cpp:176` |
| 调用方 | 编译 `.as` 模块 | `asCScriptEngine::RegisterObjectType`（`as_scriptengine.cpp:1719`） |
| 认 `<T>` | ❌ 标识符后只接受 `;` / `:` / `{`（`:3774-3810`） | ✅ 标识符后**必须**是 `<`，否则报错（`:189-194`） |
| 认类体 `{...}` | ✅ | ❌ 必须以 `ttEnd` 收尾（`:226-232`），整串只是声明头 |

`TArray` 的模板性来自这一行 C++ 注册串（`class` 关键字可选，故 `T` / `class T` 都收）：

```cpp
// [UE]Private/Binds/Bind_TArray.cpp:1338
auto TArray_ = FAngelscriptBinds::ValueClass<FScriptArray>("TArray<class T>", Flags);
```

**第三道锁**：即便绕过 AS parser，UE 预处理器的类名正则也不含 `<>`——
`(class|struct)\s+([A-Za-z0-9_]+)(\s*:\s*...)?`
（`[UE]Private/Preprocessor/AngelscriptPreprocessor.cpp:723`），`<T>` 进不了
`FAngelscriptClassDesc`。

| 操作 | 可行 |
|---|---|
| `TArray<int>` / `TMap<FName, UObject>` 使用实例 | ✅ |
| `TArray<TArray<int>>` 嵌套 | ✅ |
| `class TMyContainer<T> { ... }` 定义模板 | ❌ parse error（`Expected '{'`） |
| `void Foo<T>(T Value)` 模板函数 | ❌ parse error（`ParseFunction` 的标识符后直接是形参表，`:3420-3423`） |
| 给 `TArray<FVector>` 追加方法（特化） | ❌ 仅 C++ 侧 `registeredTemplateSpecializationFunctions` 可做 |

旁证：`as_texts.h` 中全部 template 相关错误文本都属**注册期/实例化期**
（`Cannot register`、`Template '%s' expects %d sub type(s)`、
`First parameter to template factory must be a reference` 等），
**没有一条**是"脚本不能定义模板"——因为语法层根本不认识该构造，报错落在通用
`Expected '{'` 上。引擎自带 `.as` 脚本中模板定义数为 **0**（实测）。

- **对 LSP 的推论**：`.as` 源码索引**永远不会产生** `TypeKind::Param`（类型形参只存在于
  `.d.as` 的模板定义体内）；`.as` 里出现模板定义头属异常形态，需报诊断（见 §4 第 6 条）。

### 2.6 C++ API 表面过滤

- **现象**：绑定层只暴露「能翻译成反射签名」的 API。`TFunction<>` 参数、
  返回闭包的工厂、std::function 回调统统不可绑定。
- **原因**：原则二的直接推论。绑定一个 API 的前提是它的签名里的每个类型
  都有 FAngelscriptType 实现。
- **对使用者的意义**：「脚本能调什么」不取决于 C++ 头文件有什么，
  而取决于 `Binds/` 里绑了什么。扩展能力的路径是**写 C++ 绑定**，不是在脚本里绕。

### 2.7 字段的反射策略（class 与 struct 分治）

「不加 `UPROPERTY()` 的字段会怎样」——class 和 struct 走**两套完全不同的策略**，
这是两原则在字段层面的直接体现。

#### class 字段（三分法）

| 字段 | FProperty | 蓝图可见 | 序列化 | GC |
|---|---|---|---|---|
| 有 `UPROPERTY()` | ✅（按 specifier） | 按 specifier | 按 specifier | ✅ |
| 无，纯值类型（`float`/`int`/`FVector`…） | ❌ **不生成** | ❌ | ❌ | 无引用，不需要 |
| 无，**含 UObject 引用**（`AActor A;` / `TArray<AActor>`…） | ❌ 不生成 | ❌ | ❌ | ✅ 走 **GC ReferenceSchema** |

- 纯值类型的裸字段是 **angelscript-only**：只存在于 AS 对象内存区
  （C++ 父类属性之后），UE 反射宇宙完全看不见
  （`[UE]Private/ClassGenerator/AngelscriptClassGenerator.cpp:289-290` 的 `continue`）。
  官方文档「蓝图访问不到」即指此。附带好处：零反射开销、不触发全量重载
  （改 `UPROPERTY` 字段需要 FullReload，改裸字段不必）。
- **裸引用字段不会泄漏**：UE 5.4+ 的 `GarbageCollectionSchema` 机制——
  generator 对未生成 FProperty 但 `HasReferences()` 的字段调用 `EmitReferenceInfo`
  写入 `Class->ReferenceSchema`，GC 沿 schema 扫描
  （`ClassGenerator.cpp:4833-4841`）。不写 `UPROPERTY` 在 class 里是安全的，
  代价只是不可见 / 不序列化 / 不复制。
- class 可以这么做的原因：实例本身就是 UObject，全部字段位于自己体内，
  GC 可以越过 FProperty 直扫 schema。

#### struct 字段（一刀切：强制隐藏 FProperty）

```cpp
// [UE]Private/ClassGenerator/AngelscriptClassGenerator.cpp:283-287
if (ClassData.NewClass->bIsStruct)
    bShouldMakeProperty = !PropertyType.NeverRequiresGC();
```

- struct 是值类型，会**嵌入任意宿主**（别的 class 的属性、容器元素、栈变量），
  宿主不可能知道它的布局——所以 struct 必须**自描述**：除少数
  `NeverRequiresGC()` 的绑定类型（FCollisionShape 等零引用结构）外，
  **所有字段（包括裸 `float`）强制生成隐藏 FProperty**，生成不了即 `AS0301`。
- 隐藏属性统一标记：`bBlueprintReadable/Writable = false`（蓝图不可见）；
  `Transient` 默认关闭、由设置项 `bMarkNonUpropertyPropertiesAsTransient` 控制，
  `NotReplicated` 同理（`[UE]Public/AngelscriptSettings.h:80,84`，两者默认 `false`）。

> 一句话：**class 的裸字段是「性能优化选项」，struct 的裸字段是「强制保险丝」**。
> 前者有 GC Schema 兜底所以可以裸，后者没有本体所以必须穿 FPROPERTY 马甲。

### 2.8 其它结构性限制速记

| 限制 | 一句话原因 | 出处 |
|---|---|---|
| class 禁止构造创建 | 实例是 UObject，分配权在 UE | `AS0104` |
| struct 禁止继承、自动 final | `asOBJ_VALUE + asOBJ_NOINHERIT`，映射 UScriptStruct | [专题 §6](struct类型专题.md#6-继承as-禁止但-ue-支持展平机制) |
| `import` 永远不可用 | 宿主从不绑定（运行期才报错），文法层已拒绝 | [对比文档 §5.2](原版AngelScript与UE-fork对比.md#52-清单已逐项取证) |
| 裸 enum 值禁止 | `asEP_REQUIRE_ENUM_SCOPE=1`，必须 `MyEnum::Value` | [对比文档 §5.2](原版AngelScript与UE-fork对比.md#52-清单已逐项取证) |
| 虚属性（脚本声明）无人认领 | AS VM 支持，UE ClassGenerator 零处理 | [对比文档 §5.2](原版AngelScript与UE-fork对比.md#52-清单已逐项取证) |
| mixin class 不存在 | `ParseMixin` 被重定义为 mixin **函数**限定符 | [对比文档 §5.2](原版AngelScript与UE-fork对比.md#52-清单已逐项取证) |
| **脚本不能定义模板** | 模板声明头走独立入口 `ParseTemplateDecl`，只服务 C++ 注册串；`ParseClass` 不认 `<` | [§2.5.1](#251-脚本侧不能定义模板只能用-c-注册的) |
| 增量 GC 被禁止 | UObject 引用散布在值类型/容器中，增量扫描会漏 | `[UE]Private/AngelscriptManager.cpp:260-265` |

## 3. 脚本作者速查：想要 X，用 Y

| 通用语言里的写法 | UE AS 里的写法 |
|---|---|
| `arr.sort((a,b) => ...)` | 给 struct 写 `opCmp`，然后 `arr.Sort()`（升/降序开关） |
| `arr.find(pred)` | 手写 for / foreach 循环 |
| 闭包订阅事件 | `UFUNCTION` + `Delegate.AddUFunction(this, n"Handler")` |
| 带上下文的回调 | `FAngelscriptDelegateWithPayload` + `BindWithPayload` |
| `new MyClass()` | `SpawnActor`（Actor）/ `NewObject`（UObject）/ `Create()`（组件） |
| `MyClass@ h; h = null; h is other` | `MyClass A = nullptr; A == nullptr; A == other` |
| `cast<T>(obj)` | `Cast<T>(obj)`（大写） |
| `dictionary<K,V>` / `array<T>` | `TMap<K,V>` / `TArray<T>`（`Add`/`Find`/`Remove` 绑定方法族） |
| 接口 | 继承（UE 接口类经绑定层暴露为普通 class） |
| 可空类型 | `TOptional<T>`（`.IsSet()` / `.Get()` / `.Set()`） |
| enum 裸值 `Red` | `EColor::Red`（作用域强制） |
| 「仅脚本内部用、不想进反射」的字段（class） | 直接裸声明（不加 `UPROPERTY()`）：蓝图不可见、不序列化、零反射开销；含 UObject 引用也安全（GC Schema 兜底） |
| 自定义泛型容器 `class TMyPool<T>` | **不可能**（[§2.5.1](#251-脚本侧不能定义模板只能用-c-注册的)）。按需退化：① 用现成 `TArray`/`TMap`/`TSet`/`TOptional` 组合；② 元素统一为 `UObject` + `Cast<T>()` 取回具体类型；③ 异构数据用 `TArray<FInstancedStruct>`；④ 真需要新容器形态 → 回 C++ 写 `Bind_T*.cpp` |
| 泛型函数 `void Swap<T>(T a, T b)` | **不可能**。按具体类型写重载，或把参数收敛到公共基类（`UObject`） |

## 4. 对本 LSP 项目的影响

这份取舍清单是 LSP 各模块的**需求边界**：

1. **类型系统（as-core）**：不需要建模 funcdef/函数值/闭包/句柄语义；
   回调类型的补全与签名帮助围绕「委托绑定 + `n"..."` 字面量」模式做。
2. **补全**：`AddUFunction(this, n"|` 触发时补全当前类的 UFUNCTION 名单
   （对照官方 LSP 的行为）；`BindWithPayload` 的通配参数（`?&in`）不做类型补全。
3. **诊断**：`§2` 表中的替代品是 quick-fix 建议文案的素材来源
   （如 lambda → 提示改 UFUNCTION + AddUFunction）。
4. **`.d.as` 解析**：绑定签名里存在 `?` 通配参数形态（`BindWithPayload` 即实例），
   `wildcard_type` 必须支持——grammar 已覆盖。
5. **模板（§2.5.1）**：类型形参（`TypeKind::Param`）只可能来自 `.d.as` 的模板定义体，
   `.as` 索引路径永不产生；模板实例化的输入恒为「`.d.as` 定义 + `.as` 侧的具体实参」，
   不存在脚本侧定义参与单态化。
6. **诊断（P5）**：`.as` 中出现模板定义头（`class TFoo<T>`）属异常形态，
   引擎行为是 parse error。**是否报诊断按需决定**——诊断规则由 LSP 自主设计
   （[诊断码表](../docs/诊断码表.md) §2 末段已登记素材，该表不构成实现承诺）。
7. **文档同步**：新发现「砍了什么/替代品是什么」→ 更新本文 §2/§3，
   涉及差异因果的细化 → 对比文档对应章节。
