## 0. 范围界定：什么算「基础类型」

判定标准只有一条：**是否由 VM 内建**（出现在 `[ENGINE]as_tokendef.h` 的 token 表、
可被 `asCDataType::CreatePrimitive` 直接构造），而不是由宿主通过 C++ 绑定注册。

这条线把类型分成两个世界：

| | 基础类型（本文） | 绑定类型 |
|---|---|---|
| 词法地位 | 语言关键字（token 表成员） | 普通标识符 |
| 类型真值 | VM 内建，无需注册 | `[UE]Binds/Bind_*.cpp` 注册，`.d.as` 导出后可见 |
| 典型成员 | `bool` / `int` / `float32` … | `FString` / `FName` / `FText` / `FVector` … |

「没有 `string`」是本文最常被问到的结论：**UE-AS 的字符串全部是绑定类型**（§4），
普通字符串字面量 `"..."` 的静态类型是 `FString`，由字符串工厂机制决定，不是语言内建。

## 1. 完整清单

token 表 `[ENGINE]as_tokendef.h:255-305` 中属于类型的条目：

| 类别 | 类型 | 宽度 | 备注 |
|---|---|---|---|
| 布尔 | `bool` | 1 字节 | |
| 有符号整数 | `int8` | 1 字节 | |
| | `int16` | 2 字节 | |
| | `int`（= `int32`） | 4 字节 | **词法别名**，见 §3 |
| | `int64` | 8 字节 | |
| 无符号整数 | `uint8` | 1 字节 | |
| | `uint16` | 2 字节 | |
| | `uint`（= `uint32`） | 4 字节 | **词法别名**，见 §3 |
| | `uint64` | 8 字节 | |
| 浮点 | `float32` | 4 字节 | fork 新增 token |
| | `float`（= `float64`） | 8 字节 | **默认宽度反转**，见 §2 |
| | `float64` | 8 字节 | fork 新增 token |
| | `double` | 8 字节 | 兼容保留，官方推荐不写，见 §2.3 |
| 其他 | `void` | — | 只能出现在返回类型 / 泛型参数占位 |
| | `auto` | — | 类型推断关键字，不是具体类型 |

宽度由 `asCDataType::GetSizeInMemoryBytes()`（`[ENGINE]as_datatype.cpp`）按 token 返回。

**不在清单里、容易被误当成基础类型的**：
`string`、`char`、`interface`、`funcdef`、`typedef`——token 表里全部不存在
（后三个是原版 AS 的死 token，见[对比文档 §1.1](原版AngelScript与UE-fork对比.md)）。

## 2. 浮点：默认宽度反转

这是 fork 对原版最大的一处类型语义修改，链条如下：

### 2.1 引擎属性注入链

```
[UE] AngelscriptSettings.h:161   bScriptFloatIsFloat64 = true（默认）
        │
        ▼  [UE] AngelscriptManager.cpp:344
[ENGINE] asEP_FLOAT_IS_FLOAT64 = 1
        │
        ▼  [ENGINE] as_parser.cpp:702-706
parser 把所有 ttFloat 直接改写为 ttFloat64
```

VM 自身的属性默认值同样如此（`[ENGINE]as_scriptengine.cpp:661`：`ep.floatIsFloat64 = true`），
与原版 AS 的「`float` = 32 位」相反。

### 2.2 字面量规则

| 字面量 | 类型 |
|---|---|
| `1.5`（无后缀） | `float64` |
| `1.5f` / `1.5F` | `float32` |

**显示约定**（hover / 签名帮助要用）：`[ENGINE]as_datatype.cpp:206-222` 的 `Format()` 在
`floatIsFloat64` 生效时把 `float64` 显示为 **`float`**、`float32` 显示为 **`float32`**。
即「8 位宽是默认、不显示后缀；4 位宽是特例、显式写 `float32`」。

### 2.3 `double` 的处境

- `asEP_ALLOW_DOUBLE_TYPE` 由 UE 侧 `bDeprecateDoubleType`（`[UE]AngelscriptSettings.h:173`，默认 `false`）
  **反向**注入（`[UE]AngelscriptManager.cpp:345`）：默认 `double` 可用；
- 开启 deprecate 后 parser 报 warning：`Use of 'double' is deprecated. Please use 'float' or 'float64'`
  （`[ENGINE]as_parser.cpp:720-725`）；
- 结论：脚本作者不应写 `double`——`float`（= 64 位）才是标准拼写。

### 2.4 反射侧的映射（决定 `.d.as` 里的形态）

`[UE]Binds/Bind_Primitives.cpp:660-675`：`bScriptFloatIsFloat64 = true` 时——

| C++ 类型 | 脚本类型名 |
|---|---|
| `double` | `float` |
| `float` | `float32` |
| UE `float` 函数参数（放宽兼容） | 仍按 `float`（64 位）接收，隐式收窄 |

实测 `[DUMP]` 全部为 `float32`/`float` 两形态，无 `double`（与 §2.3 一致）。

## 3. 整数的词法别名

`[ENGINE]as_tokendef.h:278-303`：

```c
	asTokenDef("int"       , ttInt),
	asTokenDef("int32"     , ttInt),      // 同一个 token
	...
	asTokenDef("uint"      , ttUInt),
	asTokenDef("uint32"    , ttUInt),     // 同一个 token
```

`int` / `int32`、`uint` / `uint32` 是**同一 token 的两个拼写**，在词法层就合并，
不存在「窄 int / 宽 int32」的区别。反射侧同样注册别名（`[UE]Bind_Primitives.cpp:679-680`
`RegisterAlias("int32", IntType)` 等）。

`.d.as` 导出统一用 `int`（414 个导出文件实测：`int32` 仅作为反射别名零星出现，
参数/返回值一律 `int`）。**LSP 的 hover/补全应跟随此惯例输出 `int`**。

## 4. 字符串：没有 `string`，三件套全是绑定类型

### 4.1 `FString`

- 值类型绑定：`[UE]Binds/Bind_FString.cpp:158` `FAngelscriptBinds::ValueClass<FString>("FString", ...)`，
  trivial 构造/析构（`:168, :182`）——语义上就是「脚本侧的 string」，但是**由绑定注册的 struct**；
- **字符串工厂**：`[UE]Bind_FString.cpp:393` `RegisterStringFactory("FString", new FStringFactory())`
  ⇒ 普通 `"..."` 字面量的静态类型是 `FString`；
- heredoc（`"""..."""` 多行字符串）同样走字符串工厂（`[ENGINE]as_tokenizer.cpp:332-345`）；
- 相邻字符串常量在解析期拼接（`[ENGINE]as_parser.cpp:1648-1653`）；
- 单引号 `'x'` 是**字符字面量**语法，仅在 `useCharacterLiterals` 引擎属性开启时有效
  （`[ENGINE]as_compiler.cpp:12182`），UE-AS 未开启 ⇒ 单引号字面量不可用。

### 4.2 `FName`

- 绑定类型（`[UE]Binds/Bind_FName.cpp`），无语言级字面量；
- `n"..."` 是**预处理器伪语法**（Layer A）：`[UE]Preprocessor/AngelscriptPreprocessor.cpp:3762-3767`
  把 `n"abc"` 改写为 `GenerateStaticName(...)` 生成的静态 `FName` 引用；
- 不进 token 表（对齐[对比文档 §1.2](原版AngelScript与UE-fork对比.md) 的「上下文关键字」分类）。

### 4.3 `FText`

- 绑定类型，无专用字面量、无预处理改写；本地化文本经 `FText` API 构造。

### 4.4 `f"..."` 格式化字符串

- 同为预处理器伪语法：`[UE]AngelscriptPreprocessor.cpp:3768-3774` 把 `f"...{expr}..."` 改写为
  `GenerateFormatString(...)` 生成的 `FString` 拼接表达式；
- **推导结果类型是 `FString`**（不是某种 format 类型）。

## 5. 字面量 → 类型速查表

| 字面量 | 类型 | 证据 |
|---|---|---|
| `42` / `0x2A` / `0b101010` / `0o52` / `0d42` | `int`（int32，按需隐式扩到 int64） | `[ENGINE]as_parser.cpp:1630` BNF:17 BITS 记法 |
| `1.5` | `float64`（显示为 `float`） | §2.2 |
| `1.5f` | `float32` | §2.2 |
| `true` / `false` | `bool` | `[ENGINE]as_parser.cpp:1627` BNF:12 |
| `nullptr` | 空句柄值（配引用类型的 null） | `[ENGINE]as_tokendef.h:289` |
| `"abc"` / `"""heredoc"""` | `FString` | §4.1 |
| `n"abc"` | `FName` | §4.2 |
| `f"x={x}"` | `FString` | §4.4 |

## 6. 附带的内置常量

`[UE]Bind_Primitives.cpp:687-770` 以 `const` 全局变量形式绑定了各类型的边界值与数学常量，
补全/hover 需要把它们当作已知符号：

- `MIN_uint8` … `MAX_uint64`、`MIN_int8` … `MAX_int64`（逐宽度成对）；
- `PI` / `HALF_PI` / `TWO_PI` / `SMALL_NUMBER` / `KINDA_SMALL_NUMBER` / `BIG_NUMBER` / `EULERS_NUMBER`，
  及 `_flt` 后缀的 `float32` 版本；
- `NAN`（`float32` 与 `float64` 两个版本）。
